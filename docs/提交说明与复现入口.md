# MeetingWatcher 项目材料

会议助手把会议发言形成可追溯的纪要和行动事项，经用户确认保存，并在下一场继续跟进原任务。材料包含完整应用演示、技术复盘、调优和评测依据。

## 建议阅读顺序

1. **01_项目复盘报告.pdf**：项目能力、系统架构、阶段演进及验证结果。
2. **演示视频.mp4**：15:13。00:07 动态纪要，02:41 动态行动事项，04:12 文字整理复用候选，05:32 第二场，06:44 起展示三人原任务进展，10:36 新方案提议，13:35 材料修改，14:32 评测证据。快放处显示“快进中”。
3. **02_任务与决策提取调优记录.pdf**：从具体错例说明改动和同口径结果，保留负结果及回退分析。
4. **测试用例_115场景.json**、**架构图.png**：测试输入、参考与判分，以及系统结构。
5. **03_配置说明.pdf**和 [GitHub 源码](https://github.com/yhnapoleon/MeetingWatecher)：运行应用、检查保存结果或继续开发。

## 源码运行

源码链接可直接提交：https://github.com/yhnapoleon/MeetingWatecher 。获取代码并运行检查：

```powershell
git clone https://github.com/yhnapoleon/MeetingWatecher.git
Set-Location MeetingWatecher
python scripts/verify_submission.py
```

需要 Python 3.11+。命令复算两场新参会组判分、运行核心定向测试并预检整会推理，不调用模型。按配置说明安装实时助手依赖后，添加 `--copilot` 可运行对应离线测试；完整应用另需 Node.js 22+ 和自己的模型凭据。

仓库保持 meeting_eval、meeting_copilot、demo、data、runs、docs 等原目录。数据和标注在 data；选定评测证据在 runs 与 docs/evidence；可编辑报告在 docs。项目仓库：https://github.com/yhnapoleon/MeetingWatecher 。

## 用例与结果

测试文件沿用历史冻结评测：115 场景对应 117 个处理单元，其中两个场景包含连续两场处理。单场输入在 jobs，跨会输入在 chains，标签在 labels，逐例任务参考、预测与判分在 task_review。标注与复核由助手完成；历史回归与当前产品运行分别报告。

当前完整演示使用 AMI 原声与实际 STT 词轴回放，运行中调用模型生成纪要、行动事项和回答。任务保存与成员邀请使用本地实现。视频贯穿同一组任务：三项任务、三次更新、六次确认，第二场没有明确新分工，新增任务为 0。
