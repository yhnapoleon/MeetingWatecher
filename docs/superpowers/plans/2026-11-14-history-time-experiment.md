# 历史日期与当前状态更新实验

目标：解释 M2 已完成却未更新旧任务的失败，并验证一个最小修复是否有效。用户已授权开始实验。本轮使用既有 Python/SQLite/ModelClient，在 experiments 内保存提示变体，不修改生产提示或校验规则。

原因：事件 time 被模型理解为任务完整时间快照，填入 history.due_date；当前证据只能引用本次会议，旧日期无证据而校验失败。Service 实际只更新 status，历史 due_date 原本无需重新填写。已有失败原始响应可确定性重现。

比较方案：

1. 明确 time 只表示当前会议的时间陈述，未提及则 unspecified；历史字段继续由持久任务保存。改动最小，本轮实测。
2. 新增历史证据来源及字段更新操作。可支持以后完整改期/改负责人，但涉及跨来源授权、版本和字段合并，当前只更新状态用不到，暂不实现。
3. 直接放行空证据 deadline。会同时允许无依据的新任务期限，不采用。

实验变体由本会话选择。单变量为解释提示末尾的时间语义约束；核验、代码、模型参数不变。

- [x] 冻结 M2 失败请求及两个原始响应，复现 Deadline requires explicit text and evidence。
- [x] 冻结 8 例输入和预期：原失败、完成未提时间、重新打开、同名歧义、非负责人代报、完成旧任务同时新增有期限工作、明确改期、明确未完成。
- [x] baseline 与 current-time 各跑一次。M2 baseline 复用原失败响应；其他 baseline 正常调用。current-time 复用对应 baseline 的跟踪/事实/决策原始调用，解释及核验重新运行；新 SQLite 状态，不复制成功结果。所有来源与新增成本保存。
- [x] 逐项核对正常 Service 入口的实际任务状态、日期、创建数和待确认信息。无写入必须伴随正常处理/必要提醒，结构失败不能算反例通过。
- [x] 若局部对照支持假设，固定变体进行独立完整 M1/M2 回放，验证跨会入口；失败保留，最多恢复一次且分别报告。
- [x] 报告结果和限制、更新 HANDOVER；本轮实验不直接切换默认策略。

验收：应更新的完成/重开正确落地；旧日期不改变；明确新期限保留；同名任务和非负责人报告不误写；明确改期不悄悄消失（当前执行器不支持改期，应保留待处理）。这些是事先冻结的行为要求，合成样例不是盲测，代理判断不是人工金标准。
