# Context-v5 缺陷修复与两轮回归

2026-11-16。会议转写中的工作状态报告现在可以进入确认或更新流程，同一段里的旧任务完成和新任务创建也能分别落库。本轮完成了代码修复及 95 个场景的两轮独立执行；**原话与用户可见输出复核通过 172/190，仍有 18 次失败，默认保持 split-v3，context-v5 继续作为可选策略。**

## 从一个失败样例看改动

HT06 的原话同时包含“上周三个登录失败案例我已经发到研发群了”和“我会整理这次支付失败的两个案例，2026年11月20日下班前发到支付群”。旧版本的初始解释已经分出了完成事件和新工作，但检查器把完成事件当成背景，修正阶段随之删掉旧任务更新；即使保住事件，Service 的独立事件策略名单也遗漏了 context-v5，会把同段更新与新建误判为冲突。

本轮将实际完成、进展汇报纳入工作信息，并补齐 Service 策略接入。最终两轮 HT06 均把旧登录任务置为 done，保留旧期限，同时创建截止 11 月 20 日的新支付任务。HT05 的第三方完成汇报则进入确认入口，旧任务仍为 open；C17、P11a 的已发送和正在归档分别进入 completed、progress 报告，不新增待办。

[HT06 第一轮结果](../runs/2026-11-16-context-v5-fixes/full-compact-final/r1/updates/HT06/result.json)及其[tasks.json](../runs/2026-11-16-context-v5-fixes/full-compact-final/r1/updates/HT06/tasks.json)保存了提取与实际 SQLite 状态。所有写入验证均使用模拟器。

## 实现与边界

| 改动 | 对应机制及验证 |
|---|---|
| Service 接入 context-v5 | 同段独立新建、更新均可执行；正常入口测试覆盖实际落库、重复处理幂等，split-v3 原冲突保护保留。 |
| 原文编号与增量追踪 | 模型输出当前目录的 Q 引用和新增实体、线程、更新；程序展开逐字原文并保管历史。更新按新增段落顺序追加，拒绝未知或未来证据、旧 ID 替换，不重排旧历史。 |
| 检查目标与参考分开 | 明确可输出的记录和事件字段；只读背景不携带普通可输出身份。covered 处置仍能查询必要旧记录，额外及未知键继续严格拒绝。 |
| 报告、承接定义一致 | work 包含实际状态汇报；不同动作的完成和进展分别保留。assigned 表示尚未接受，accepted 需要对应人的接受证据。 |
| 覆盖检查输入 | 未引用原文和无关联线程的实体提供给检查器；首次解释遗漏的孤立实体仅补 entity_only，不直接生成工作、事件或问题。 |
| 工作时段规范化 | 仅对 new + future_work + work_window + set 且有文本和证据的事件，把 change 改为 keep。保留时间含义、原响应及后续核验；旧任务不适用。 |

生产改动共 7 个文件，见[变更及哈希](../runs/2026-11-16-context-v5-fixes/production-changes.json)。项目测试 **217 项**、实验测试 **35 项**通过。独立[代码审查](../runs/2026-11-16-context-v5-fixes/final-code-review.md)确认 56 份生产代码和提示与启动快照逐字节相同，未发现新的确定性代码缺陷。

entity_only 和覆盖提示只是增加被检查的机会：某段被引用，不代表其中所有工作均已覆盖。冻结旧漏提上游的快速检查探针仍未补回 UI 工作，因此不能宣称补漏机制已经稳定解决该问题。

## 最终回归结果

使用 deepseek-flash、原 compact-check 配置，并发 4；追踪和解释开启 high 思考，检查关闭思考。93 个单场场景加 2 个完整 M1→M2 Service 场景，每个运行两次，使用新请求目录和数据库，无网络或格式重试，保留算法原有的一次语义修正。

P03a/P12a 的用户裁定在启动前迁入新 manifest；C03 仍按冻结标签评分，未硬编码角色。每例对照原文检查工作内容、负责人、日期、报告、确认问题和未决事项。最终通过要求自动契约和语义复核同时通过。

| 范围 | 自动契约通过 | 结合原话复核通过 |
|---|---:|---:|
| 第一轮 | 91/95 | 85/95 |
| 第二轮 | 92/95 | 87/95 |
| 合计 | 183/190（96.3%） | **172/190（90.5%）** |

95 个场景中，83 个两轮均通过，6 个两轮均失败，6 个发生通过/失败翻转。原始响应、评分、190 份带输出哈希的复核记录和汇总见[最终证据目录](../runs/2026-11-16-context-v5-fixes/full-compact-final/final-report.json)。汇总检查确认输入集合无重漏、输出未在复核后改变、生产快照一致、请求及 token 计数一致。

此前剩余缺陷涉及的 9 个场景，按相同工作要求对比，从 **6/18 提高到 17/18**：

|---|---:|---:|

| C03、P11a、CP02、PF02、CP07 | 各 1/2 | 各 2/2 |

C14 旧失败是更新顺序倒退，本轮失败是第一轮追踪响应 JSON 语法错误；第二轮条件性调研正常保留。[对照数据](../runs/2026-11-16-context-v5-fixes/targeted-comparison.json)的修前结果包含之前记录的网络恢复，本轮则为全新首次执行。该对照只支持这些已知缺陷场景的变化，不代表全量净提升或单项改动的因果效果。

旧报告的 168/190 首次结果及 178/190 网络恢复后结果保留。此次复核发现旧结果也漏记了 C09、P05a、P06a 等用户可见未决问题错误；**不能直接把旧 178 与本轮 172 当作同口径的升降比较**。新旧逐例差异及恢复来源见[独立语义复核](../runs/2026-11-16-context-v5-fixes/semantic-review-differences.md)。旧总分没有被追改。

## 剩余 18 次失败

这些失败对应 12 个场景。逐例原话判定、自动失败项、异常和输出哈希见[失败索引](../runs/2026-11-16-context-v5-fixes/full-compact-final/failure-index.json)。

| 类别 | 次数 | 具体表现 |
|---|---:|---|
| 未决事项或描述偏移 | 10 | C09 两轮把已明确的关注方向仍列为未定；P05a/P06a 两轮及 P05b 第一轮把引用问题列成本场未决；C13 第二轮把复盘结果写成遗留问题；P08b 两轮把了解录像支持情况改成“小林能否支持、查到录像”，第一轮另加“会议”限定。 |
| 引用情境误作本场提议 | 2 | C24 两轮把转述教师过去常问的问题变成待采纳提议。 |
| 多余追问 | 2 | C11 第一轮把产品备选方案变成采纳追问；C20 第二轮为仅提及的文稿增加处理问题。 |
| 确认缺口问错 | 1 | HT04 第一轮正确阻止更新两条同名旧任务，却询问是否承接；应只问对应哪条旧任务。第二轮正常。 |
| 输出截断 | 2 | CP01 两轮 track_context 均耗尽 16,384 输出 token；第一轮推理占16,384，第二轮占15,922，最终响应不完整，工作未进入后续解释。 |
| JSON 语法错误 | 1 | C14 第一轮 track_context 返回非法 JSON。 |

前 10 次中的多项来自独立 facts/unresolved 分支。工作分支已经正确识别引用情境或最终任务，通用纪要分支仍生成相反的未决事项，Service.minutes 又直接展示它们。应从最终输出的一致性处理这个共同问题，而不是只继续强化工作提示。C24、C20 等则仍是工作分类边界问题；没有消融证据，不能将这些错误归因于某一句新提示。

P12b 第一轮将“改好灰度配置并发测试”写成“进行并发测试”。独立复核确认原句存在“并／发测试”和“并发／测试”两种读法，因此撤回最初的明确错误判断，只作为输入歧义观察项，不扣分。不能用旧设计意图替代本场原文。

## 下一步与结论边界

1. 先处理最终纪要中工作结论与 unresolved 的冲突，验证 C09、C13、P05a/b、P06a、P08b，并保留真实尚未决定问题。
2. 处理 CP01 推理耗尽及 C14 格式错误。当前 API 请求只有 json_object，schema 在消息数据中，本地才严格校验。官方文档列出了 Beta 工具调用的 strict schema 模式；本项目尚未接入或实测，不能把其文档能力写成现有保障。[DeepSeek strict 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)
3. 核对 C24 的引用范围、C11/C20 的追问边界，以及 HT04 确认缺口和问题的对应关系。采用少量明确失败输入验证机制，再决定是否继续扩大回归。

这批语料此前已被查看并用于调优，是回归集而非盲测；190 次是 95 场景的重复执行。主复核由助手完成，独立代理审查代码并复核七个争议案例，不是独立人工真值集。测试和已知缺陷场景改善支持保留本轮实现，剩余失败及两轮波动不支持切换默认策略。
