# 正常对话理解、核验纠错与标注复查

用户目标：合理的上下文理解可直接成立；核验指出实际错误，不能通过想象另一种可能性制造缺口。验证后接入一次自动修正，并检验时间修饰对象。

## 设计与实验

1. 保留协议5源码和既有输出，复查 C02/C03/C09/C26 原文及源语料。C09 的必需内容改为“营销角色研究说明书相关问题”；消费者看法可作为合理具体化，不作为唯一正确答案。旧标签保留，新审计口径另存。
2. 比较 A：固定旧解释，仅换成语用核验；B：同时修正解释和核验。核验优先采用说话人、对话目的、分工结构和相邻回应共同支持的解释，只有实际否定、转题、不同负责人或真正竞争目标才报告问题。明确工作与可选研究方法分开。
3. 接入 C：核验指出记录或字段错误后，限定目标记录重解释一次，再独立核验。其他记录及事件保持原样。改正失败保留初次核验结果，在 trace 记录失败，不抹掉已成立工作。必需的首次解释/核验结构失败允许原有 resume；附加修正不在正常 Service 中重试，语义不通过不循环。
4. 用正常 Service 入口验证原6难例、时间修饰对象对照、短回应正反例、旧任务状态/日期更新。比较任务内容、承接、操作及实际持久化结果。使用首次输出，单独呈现标注调整的影响。
5. 程序测试覆盖补事件、撤事件、非目标保持、修正复核失败、缓存恢复。最终一次独立代码审查；更新交接和结果。

## 调研依据

- [Purver 等，2007](https://aclanthology.org/2007.sigdial-1.4/)：以讨论、安排和承接构成的对话片段提取工作，适合本项目按对话功能连接短回应。
- [Plank 等，2014](https://aclanthology.org/P14-2083/)：语言标注的分歧需要区分解释差异与错误。这里将源摘要的具体表述与输入逐字稿可支持的最低要求分开。
