# 跨会议决策重申与版本变更

第二场会议说“沿用首批报名只面向会员的规定”，随后将年费从 99 元改到 89 元。此前查询当前规定会得到三行，两行都是会员资格。修复后同一查询得到两项：首批仅限会员，年费 89 元。按第一场结束时间回看，年费仍为 99 元。两次资格确认和两次价格决定共四条历史，每条保留本场的发言 ID 和原话。[原始结果](../runs/2026-11-18-decision-system/service-final/storage.json) · [新版结果](../runs/2026-11-18-cross-meeting-reaffirmation/live/storage.json)

## 如何登记和查询

系统原先为每场决定产生独立记录，查询时只根据 `supersedes` 隐藏被替代的记录。现在每场仍保存自己的原话，重申时用 `reaffirms` 指向同一版本的一条历史记录。对象、范围、条件和取值都一致时才关联；明确修改时沿用 `supersedes`。已有可见记录的属性和决定文本逐字相同且唯一时，Service 可直接关联；中文改写由启用了 `--strategy context-v5 --review-decisions` 的最终裁决节点结合原话判断，使用同一次模型请求。历史目标须来自传入的有效清单并与当前属性一致，两种关系互斥。[最终裁决](../meeting_eval/decision_review.py) · [历史关系提示](../prompts/decision_history-v1.txt)

查询按指定时点和读者可见范围，显示每个有效版本最近观察到的可读记录。替代关系指向旧版本的任一次重申，都能撤下整个旧版本。后续确实改回原值时，会产生一个新版本。给下一场会议准备上下文时，以该场全体受众的可见范围选择来源；历史记录或关系目标被撤权时，查询会隐去相应内容。旧库可以直接查询：对于逐字相同且唯一匹配的跨会决定，读取时还原关系，原始库无需改写。旧库中只有语义相似、无关系字段的条目仍可能各自显示。[Service](../meeting_eval/service.py) · [版本查询实现](../meeting_eval/decision_history.py)
