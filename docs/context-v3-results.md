# context-v3：方案实施与检验结果

2026-11-15。**已实现可选策略 context-v3。C19、HT04、CP01 各两轮达到本轮目标；C23 仍不完整。完整跨会和明确落实正例各两轮通过，但定向保护样例仍有失败，因此不替换默认策略，也未晋级完整语料回归。**

本轮完成研究、设计、实现、独立代码与来源语义复核，新增 13 项程序测试，全套 184/184 通过。真实模型共 203 次调用、1,289,203 tokens；其中一次结构恢复另计 1 次调用、6,315 tokens，恢复仍失败。全部响应已收到，本轮没有传输失败。所有平台写入仍为本地 SQLite 模拟。

## 1. 研究如何转成设计

考虑过继续补提示、另加独立裁决器和调整现有接口三种方案。本轮选择第三种：上轮已经证明单独分类正确仍可能被下游推翻，而新错误集中在重复字段、双份工作描述及真实缺口的状态路由。

- Anthropic 的 [evaluator-optimizer 模式](https://www.anthropic.com/research/building-effective-agents)强调可明确评价的标准和有效反馈。本项目将“描述是否忠实”与“是否还需要用户选择”分开，避免以反复调用代替统一定义。
- [引用接口文档](https://platform.claude.com/docs/en/build-with-claude/citations)将引用限定在输入文档及位置范围。本项目借鉴这一约束，给解释与修正阶段提供程序生成的 Q 编号，再还原精确来源；没有迁移模型供应商，也没有使用其原生引用 API。
- [RARR](https://arxiv.org/abs/2210.08726)通过查证与修订改善归因，同时尽量保留原输出。本轮结构恢复保存失败输出和具体错误，要求保留身份及未受影响的语义。这个研究方向不能保证本项目的恢复会成功，实际 M2 恢复仍失败。

具体接口见[设计文档](superpowers/specs/2026-11-15-context-v3-design.md)和[实施计划](superpowers/plans/2026-11-15-context-v3-implementation.md)。

## 2. 实际实现

| 改动 | 系统行为 |
| --- | --- |
| `context_protocol_v3.py` | 模型只判断分类、内容支持/遗漏和各字段是否需要确认；程序派生旧内部 verdict/issues、提问状态和阻断范围，继续经过原严格校验 |
| 单一任务描述 | 模型只生成 record.description；event 与最终 item 复用它，不再独立生成另一份较短描述 |
| 独立内容遗漏字段 | content.missing_details 保存遗漏的必要内容及证据；content_audit 和具体说明进入修正输入 |
| Q 引用 | 解释/修正通过当前完整会议的 Q 编号选证据；程序展开为精确全段 span，未知 Q 被拒绝，修正不重新编号 |
| 共同潜在需求规则 | 跟踪、解释、核验及修正使用同一份政策；潜在需求需有原文建立的目标/期望改变/待处理选择及 need_basis，普通现状不自动变成任务 |
| 关联选择 | ambiguous 必须有至少两个不同且授权的 candidate_guids；具体选项进入用户问题，仍不创建或更新任务 |
| `reduce_v3` | 不给真实关联不明的旧完成/进度/重开汇报附加新工作承接缺口；真实承接疑问及核验不足继续保留 |
| 结构恢复 | 仅在显式 resume 时附 validation_feedback；保留失败 dict，解析失败时保留原文本/结束原因；成功上游及恢复成功结果复用原缓存身份，无自动额外重试 |

保留 context-v1/v2，默认仍为 split-v3。新增策略版本为 9，提示和代码摘要纳入配置隔离，使用新的数据库/输出目录。v2 的核心协议、合并与 reducer 文件没有修改。

Q 引用目前覆盖解释和修正；跟踪仍使用既有精确引文协议。全段引用降低了定位负担，但细粒度字段是否确由该段支持仍需要语义核验，不能把编号存在等同于语义正确。

## 3. 四个原失败样例的结果

| 样例 | context-v2 已知问题 | 最终 context-v3 两轮 |
| --- | --- | --- |
| C19 | 重复短引文定位失败；恢复后漏 question issue，再次 partial | **2/2 达标**：完整保留问题整理、请老师解答、文字稿及公众号发布，为一项团队候选，仅确认个人负责人 |
| HT04 | 真实关联选择被字段矛盾和 insufficient 状态阻断 | **2/2 达标**：列出两个授权 GUID 与摘要，只问 relation，不多问承接，零新建/更新 |
| CP01 | 命名背景被提为潜在需求，修正后留下解释争议 | **2/2 达标**：只保留小林整理移动端设置页清单，排除登录页，没有额外背景待审项 |
| C23 | 最终 item 丢失核对未听清内容的目的 | **0/2 达标**：信号背景进入 item，但仍没有表达回访需要核对/补问未听清内容 |

C23 第二轮实际 item 为：“会后由说话人一方单独联系袁校长，沟通其他几个问题；同时提到讲话过程中信号不太清楚。”最终描述已与 record 统一，但模型仍把信号问题当成附带事实。核验还明确认为它不影响工作内容，missing_details 为空。这说明数据传递缺口得到处理，语义上是否把背景理解为必要联系目的仍未解决。独立来源复核也判定两轮 content_complete=false，未放宽原评分口径。

C19 第二轮核验理由出现“请老师参与整理”的归属偏差，但最终 item 没有把整理责任转给老师。来源评分针对实际产出，不用核验理由证明最终内容正确，也不把未进入 item 的理由偏差混算为任务错误。

CP06 作为保护对照两轮均保留真实潜在需求：用户不阅读指南的问题明确关联减少重复咨询目标，做法和负责人仍待决定，没有自动生成确定实施动作。CP05 的说明书/设备实体保留且无任务；CP07 在后文明确分派承接后生成一项完整调查工作，没有旧隐式需求问题。

## 4. 跨会与保护检验

| 检验 | 结果 |
| --- | --- |
| 完整原始 M1→M2 | 两轮首次通过：同 GUID 完成、期限保留、决定替代、零额外范围任务/待审 |
| 完整明确落实正例 | 两轮首次通过：唯一陈可改灰度配置并发测试任务，截止 2026-11-16；原任务仍完成 |
| 权限/历史/幂等 | 四次完整回放均通过，包括重复处理、重启、历史查询和任务/决定/intent/审计记录不增长 |
| 最终定向可观察契约 | 26/28；每轮 13/14 |
| 最终定向来源语义复核 | **24/28**；每轮 12/14。每轮还扣除 C23 不完整 |
| 程序回归 | **184/184**，其中本轮新增 13 项 |

上述定向集是 14 个已知问题与保护样例各两轮，不是新盲测或完整 30 段语料分数。没有据此推算全量召回率。

两个额外失败必须保留：

1. **隔离 M2 第一轮失败。** 核验将范围决定重新解释为遗漏工作，并同时输出 relation=new_work 与 related_record_ids=[R2]，违背覆盖协议。流程在修正计划前被拒绝。一次携带原输出和错误的结构恢复仍重复此矛盾，不能算恢复成功。第二轮隔离 M2 通过；两次完整跨会也通过，但不同输入历史下的这些成功不能覆盖这次失败。
2. **同段另一工作第二轮修正失败。** 真实发送测试结果任务保住了，但范围记录的 kind 与核验理由不一致，触发了不必要的分类修正。目标只允许 R2/T2，模型却返回 R1/R2/R3 全部记录，因未选线程被拒绝，留下额外 interpretation_unresolved。第一轮该例通过；第二轮不能只看真实任务还在就判整例通过。

这两处表明：精简 record 缺口协议尚未解决所有覆盖关系表达和局部修正输出约束；分类理由与分类值的语义一致性仍有风险。下一轮应直接检查覆盖协议的关系不变量在提示中是否完整表达，并评估能否由程序绑定修正范围，减少模型重复输出确定性身份信息。C23 则需单独检验必要目的的因果理解，不能用增加“信号”字样解决。

## 5. 首次记录、修订和恢复

初版定向计划含 14 例，实际七个既有样例完成 21 次调用，其中对象竞争例因 gap 元素缺字段失败。其余七个新增输入漏了正常入口需要的 source_key，验证脚本在调用模型前失败；修复脚本后另建批次，没有把未执行例算成通过或模型失败。

第一次修订补齐 gap/missing_details 元素示例，14 例可观察契约为 10/14：出现事件核验重复 ID、覆盖字段缺失、真实选择被误关，以及 HT04 多余承接缺口。第二次修订统一展开所有空对象数组的元素结构，强调真实未决选择仍需要 gap，并接入授权关联选项及 v3 输出规则。最终两轮采用同一冻结版本，不再按失败样例无限追加语义提示。

独立代码审查确认缺失内容进入 repair，关联选项受授权校验，真实承接疑问没有被删除，恢复成功后不会重复调用。来源语义审查独立复核 C19/C23/HT04/CP01/CP06 共十份结果，C23 两轮仍失败。代码测试通过与模型语义效果分别记录。

扩大回归的晋级门槛未满足，因此本轮没有继续跑完整 30 语料、33 对照、10 行为和 13 更新套件。完成的四次 Service 回放用于核对原跨会核心路径；它们不替代尚未执行的全量检查。
