## 4. 本轮为何判为失败

目标是修复 v3 残留并改善最终任务产物，而不是只让结构更易校验。实际结果如下，均按最终内容、操作和多余提问判分：

| 八例中每类三轮 | A | 最终 B | 最终 C |
| --- | ---: | ---: | ---: |
| 隔离 M2 | 3/3 | 2/3 | 2/3 |
| 明确落实正例 | 3/3 | 3/3 | 3/3 |
| 上游已识别的同段第二工作 | 3/3 | 3/3 | 0/3 |
| 上游故意遗漏的第二工作 | 0/3 | 0/3 | 0/3 |
| C23 原文 | 0/3 | 0/3 | 0/3 |
| C23 改写 / 明确目的 / 无关背景反例 | 各 3/3 | 各 3/3 | 各 3/3 |
| 合计 | **18/24** | **17/24** | **14/24** |

后三个 C23 对照的冻结上游已正确，结果只证明没有破坏，不能算“修复了原 C23”。首次未修版本 B 为 16/24、C 为 17/24，也都保留。最终 A 复用未改变的首批结果，B/C 是修复后的第二批；三轮小样本不代表统计上的普遍优劣。

本轮结论不是“每个功能全面退化”：明确落实等能力保住了，身份和范围约束也通过测试；但结构版没有产品效果收益，QA 明显更差，因此整体修复实验失败。

可复用的失败经验：

- 不让模型填写冗余身份/关联字段，能消除部分非法表示，却不能证明它判断的工作成立。M2 可以从“结构失败”变成“结构合法的错误提问”。
- 拆出独立问答阶段并不等于独立可靠判断。来源阶段可能选错问题，核验阶段可能再次接受同一错误。
- 覆盖发现必须检查原文是否还有另一项工作；只证明已有 records 正确，不能证明没有漏项。
- 不能让背景记录或 trace 中的信息代替最终任务描述的完整性，也不能放松一致性校验来消除 QA 报错。
- 只查任务数量、数据库更新、M2 输出会漏掉候选和 M1 解释争议。程序测试与模型语义评分必须分开。

## 5. 当前问题及已定位的层次

### M2：决定和实施动作仍混淆

原话：“登录改版第一批的范围今天改一下，内部员工和试点客户都开放。”既定场景将其标为范围决定替代；没有另派人改配置等实施动作。预期完成旧任务、保留原期限、替代旧决定，零额外范围任务或负责人/承接问题。正例另外明确说“陈可今天下班前改好灰度配置并发测试”，并由陈可接受，必须保留。

v3 曾出现 `new_work + related_record_ids=[R2]` 的协议矛盾；实际提示确实漏了旧规则。本轮补了提示并约束结构，但最终 B 仍有一轮把 R2 变成需要负责人/承接的工作。**已确认的问题是分类判断跨阶段不一致；尚未证明唯一的上游因果来源。** 最短失败入口：[B-r2/M2](../runs/2026-11-15-context-v4/small-v2/B-r2/M2/summary.json)。

### 同段第二工作：已有工作能保留，真正遗漏却发现不了

同段明确追加：“另外，陈可今天下班前把测试结果发给客服。”上游已有 R3 时 B 3/3；上游故意不提供该记录时 B 0/3，三轮都没有提出 `new_work_findings`。这是覆盖发现失败，不是程序丢弃已发现工作。对照：[B-r1/G-omitted](../runs/2026-11-15-context-v4/small-v2/B-r1/G-omitted/summary.json)。

C 能发现这项新工作，但来源问题又错误纳入范围决定。只看 work 描述的回答不能证明范围背景，核验却用 context_only 的 R2 判 covered，触发 `Covered requirement lacks matching description answer`，整轮失败。不能允许背景冒充任务覆盖来“修好”报错。入口：[C-r1/G-omitted](../runs/2026-11-15-context-v4/small-v2/C-r1/G-omitted/summary.json)。

### C23：必要目的关系仍漏掉

原话：“还有其他几个问题，会后我们单独再联系刚才袁校长，那个讲的过程中，你这个信号也没有太听清。”“好的，所以稍后会单独联系。”冻结标签要求联系中保留核对/补问未听清内容的目的。当前最终任务只是“联系袁校长沟通其他几个问题；同时提到信号不清”，并未建立目的关系。

v3 已消除 record/event 双份描述漂移，因此当前不是那处数据传递问题。C 组三轮 `source_requirements=[]`，连必要信息问题也未提出。补入同一会议 context[54][5:7] 的真实前文仍 0/3。原话的目的关系带有口语推断，允许后续独立重审来源与标签边界；本轮没有改标签，不得把改标签算作模型提升。入口：[C-r1/C23](../runs/2026-11-15-context-v4/small-v2/C-r1/C23/)、[窗口探针](../runs/2026-11-15-context-v4/source-window/)。

### M1：潜在需求/背景和修正协议仍有残留

原话：“上线后要不要再做个监控面板？先放着，今天不定。”部分回放在 implicit_need 与 context_only 之间反复；一次修正留下需提问类型却没有 question，另一次再核验输出非法 gap 字段，均留下 interpretation_unresolved。
