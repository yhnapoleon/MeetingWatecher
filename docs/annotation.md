# 标注指南 v0.2

以会议中一件可独立交付、完成或改期的事项为一条任务。发言段只是证据单位。一人连续说“我周三发报告，周五部署新版”，两件事可以分别验收，标两条；前一人提出需求、后一人只说“我来”，合为一条并引用两段。

## 每场怎样标

主评测向模型展示每段原话的说话人、上游可用的姓名与已核验人员引用。标注者另行写任务负责人、期限、动作及证据。把“陈可说王宁负责”和“陈可说我来”分别标为王宁和陈可负责；以自动指派为评测目标时，还要检查对方是否承接及账号能否解析。公开语料有编号时展示编号，真实名字仅有人工事后查证时写入诊断记录。[首批模型输入](../data/pilot/input.jsonl) · [待复核标注表](../data/pilot/annotations.csv) · [来源与格式](../data/pilot/sources.md)

1. 登记会议系列、日期与时区、原始文件、原始说话人标签、媒体情况与使用范围。给每个发言段分配稳定 ID。保留原文和口误；听录音校正的内容另存，区分“转写可见”与“听音可知”。
2. 通读整场再定任务。记录交付动作与对象、负责人原话及证据、原始期限、规范化日期、证据段列表。发言者、被指派者和已核验的平台账号分别记。缺失字段填 null。“下周看情况”保留措辞和不确定性。“周五下班前”在已知会议日期时可解析到日期，具体钟点仍留空。
3. 给相似但无需新建的片段写一句原因，例如“只是建议”“引用上周决定”“后来明确取消”。同会先承诺后撤回时标明承诺及撤回的两段证据，在会后最终操作中排除新建。
4. 单独标纪要关键事实与决策。记录决策的主语、采用方案、适用范围、证据、是否明确替代旧决定。只有“有人提了方案”时，标未决问题。“继续原方案”链接原决定；新讨论出现类似词时先核对项目、对象和范围。
5. 对连续会议，先封存会前任务表、查看身份、允许/禁止返回的对象，再读本场发言标更新。历史任务标 GUID；同一件事的进度汇报、改期或交付，记录更新目标、先前状态和依据。对录音直接标开始/结束时间；没有录音的文稿时间只代表转写定位。

## 首轮争议的试行答案

| 原话或情形 | v0.1 标注 |
| --- | --- |
| “谁接一下？”“我来。” | 明确认领；同时引用询问与回应。没有可信账号映射时保留说话人标签和待指派状态。 |
| “小王把方案发一下。”小王没回应 | 记为明确指派、承接未确认；首轮暂存候选。保留这一类标签，便于带教决定自动建任务后重新计算。 |
| “我试试看明天能不能好。” | 标承诺强度/期限不确定，不能给出确定的明日交付。业务口径有争议时记录原话。 |
| “我发了上周那三例。” | 在同项目、可见候选唯一且发言者是原负责人时，试行策略允许完成原任务。第三方说“他应该发了”只标待核实进展。 |
| “那个方案换成 B。” | 历史中能唯一定位时连 supersedes 边；同名对象有多个时标待澄清。 |
| “用屏幕上第二个。” | 有画面时标语音段、帧/页及被指对象；纯文字时标画面依据缺失。 |

## 从样例到可评分批次

随附 JSON 中的 expected 是设计者给出的试行答案。实际标注时先由一人根据原件填写，再让复核者检查争议项、未知字段和跨会关联。记录样例 ID、原判断、修订依据、标注版本；经复核后标为 reviewed。采集端可以看到整份会议，提供给特定身份的模型输入需经过权限过滤；评分端保留禁止返回的对象作为负例。

冻结数据时以整个会议系列为单位切分。模型输出的语义改写有歧义时，复核动作、交付物和证据后记入匹配表。原始语料的自动摘要、模拟任务回执、独立人工标注分别记录来源。这使“模型命中公开行动句标签”和“系统真的把任务交给正确的人”可以分别计分。

## 正常上下文与标签粒度

负责人在安排后给出简短接受，可结合问答目的和分工结构标注承接。只有原文实际出现转问、不同回应者、拒绝或限定接受范围时，才据此判断其他指向；理论上的另一种可能性不单独构成缺口。

必需内容应以模型实际获得的逐字稿为准。源摘要可能选取一种合理具体化，不能将其所有细节都设成唯一正确答案。例如询问下一场会前研究什么、回答“说明书”并解释使用背景，支持研究说明书相关问题，不必限定为调查消费者看法。团队询问安排也不必等于某个个人承接。审计时保存旧标签、原话依据和新版本，对同一预测同时计算两套口径，见 [本次审计](../data/action-semantics-v2/pragmatic-audit/README.md)。
