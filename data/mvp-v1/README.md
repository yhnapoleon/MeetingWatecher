## 如何取数与判分

- [抽取输入](input.jsonl) 每行一个片段。每段给出稳定发言 ID、说话人标签、上游提供的角色或人员引用、原话和可用时间戳。AMI 另给来源可核查的参会名册，便于把“工业设计师”解析到一个未在该段发言的人。VCSum 的“说话人 5”只在本场有效。展示文本采用“说话人 + 时间／下一行原话”的项目示例格式。
- [标注答案](labels.jsonl) 的 35 条事件包括 8 条可模拟新建、10 条待核实或待指派、8 条无需操作、5 条决策，另有备选方案、当时判断、完成报告、进度各 1 条。负责人分为语料中可解析的个人、会内编号、团队。抽取时保留所有 18 条行动候选，模拟自动建任务只取其中 8 条。AMI 人员代号仅在这个离线环境中充当可解析身份。
- 每个行动项有一个 action_anchor，指明最能标识这项交付的原始发言段。evidence_ids 可另含问题、范围、承接或时间上下文。work_window_text 记录约定的工作时段，due_text 保留交付相关的原始时间说法，due_date 只接受可归一化的日期。本批 6 条有时间措辞，公开片段中确定日历截止日期的正例为 0。
- [划分表](splits.csv) 按 AMI 团队系列和 VCSum 原视频编号切分。开发集 21 段（英文 13，中文 8），24 条事件。保留集 9 段（英文 5，中文 4），11 条事件。两边各有 5、3 条可模拟新建。调提示或选阈值用开发集。AMI 不同团队做过相同设计题，保留集仍有领域重复。
- 5 条 prior_label 从当前事件指向较早事件，4 条跨场，1 条同场。例子包括上一场承诺整理纪要与下一场报告寄出、同一功能从成本可行到最终未纳入。prior_relation 表示交付报告、进度、答复或方案演变。C18 的答复可联系到 C14 的问题，发言没有指明场次，此边待重点复核。评关系时按同系列会议顺序与当前时间提供可见历史输入；标签 ID 只在评分端用来对齐预测。本批关系均为本项目推定。
- [视频索引](media.csv) 给出每个剪辑在原会议的起止毫秒，前后各留 1.2 秒以便回听。剪辑内定位为原始发言毫秒减去索引起点。18 个文件都已检查音视频轨时长，并抽取音频与原轨同一时间窗做波形核对。转写时间和说话人按 AMI 源标注核对，逐帧指认、人工校时和中文音视频评测仍需另取样本。[原件、来源和校验值](manifest.json)

## 运行

在项目根目录用 Python 3.11 或更新版本执行。空预测模板可直接运行，便于看清分母，再用同格式填入模型输出。

```powershell
python scripts/verify_mvp_dataset.py
python scripts/score_mvp_actions.py data/mvp-v1/predictions.dev.template.jsonl --split dev
```

评分输入每个片段一行，无检出时 items 为空列表。下例为开发集 C02 的一个预测，其余 20 行也要保留。owner_kind 取 corpus_person、speaker 或 group。已解析个人按 owner_ref 判人，会内编号或团队称谓还要检查 owner_label。

```json
{"case_id":"C02","items":[{"action_anchor":"ES2002a.B.dialog-act.dharshi.196","evidence_ids":["ES2002a.B.dialog-act.dharshi.194","ES2002a.B.dialog-act.dharshi.196","ES2002a.A.dialog-act.dharshi.42"],"operation":"create","owner_kind":"corpus_person","owner_label":"ID","owner_ref":"MEE006","due_text":null,"due_date":null}]}
```

评分器按片段及核心证据段一对一匹配，重复预测计多报。分别输出行动定位和新建定位 P/R/F1、匹配项的负责人和时间字段命中数、证据覆盖与错误 ID。这个分数衡量定位、分类及字段提取。任务描述的语义正确性需要在复核表对照原话检查。开发集有 12 个行动锚点，保留集有 6 个。空字段命中数和有日历期限的正例分母分别展示。模拟会前清单可用项目已有的 score_recap.py，预测格式见[示例](../../examples/recap_prediction.json)，目标文件换成 [workflow/expected.json](workflow/expected.json)。scenario.json 是测试驱动器用的全量状态，按查询时点回放事件并做权限过滤，再把允许项交给模型。

## 哪些结果可用于下一步

本版为基于公开证据的首轮项目初标，状态统一为 agent_labeled。校验脚本已核对原始发言、时间、人员、引用、系列切分、附件校验值和六个模拟答案。当前按用户约定使用此版本开展基线评测。后续复核可先检查开发集 C02、C03、C07、C09、C19、C26，重点看简短同意是否对应当前分工、团队承诺能否指派、时间表达是否真是截止。复核者在 review.csv 填 reviewer、correction，将调整同步到 labels.jsonl，冻结新的参考答案版本，并用已保存的预测重算分数。

下一批按首轮错例补中文团队工作会、明确到日的交付、改期和撤回、必须看共享画面才能判定的指代，并选少量完整会议盲标，检查只截高信息片段容易漏掉的事项。可将新来源整组保留，用来观察长会议漏项和主题迁移。
