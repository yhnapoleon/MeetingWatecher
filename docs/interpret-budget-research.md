# GN29解释预算与分批处理：调研和修复设计

2026-11-17。本文只提出方案，没有修改生产代码或发起模型请求。推荐先验证低推理强度能否在现有32K生成上限内完成解释；只有这条路径仍因生成规模失败，才实施按线程分批输出。任务召回率和准确率是质量验收指标，JSON完成率是独立的技术指标。

## 现场说明了什么

最近一次GN29已经跟踪完398段发言。解释输入由151,832降至67,484 token，第一次16,384个生成token全部用于推理；第二次32,768中29,681用于推理，最终JSON仍截断。引用补丁只能修复完整、可定位的草稿，因此没有触发。问题已经从跟踪失败转移到解释生成预算。详见[上一轮报告](interpret-reliability.md)。

GN25也先耗尽16K，再用23,188个生成token完成，其中20,751用于推理。最终任务命中2/3，比上一轮3/3少了条件性支付参会费。这说明“接口完成”不能代替任务验收，也不能预先认定降低推理强度不会损伤召回。

本次只读核查发现，GN29最终ledger含67个实体、13个线程；GN25含19个实体、4个线程，两者links均为空。GN29线程T10/T12/T13累积内容明显较大。这里的13个线程不是13个金标任务；线程还包含讨论、状态与背景。现有代码要求解释结果覆盖全部线程，work记录与event一一对应，随后对完整结果做核验。不能把它切成几批后直接交给要求全覆盖的旧校验器。

现在可以确认的是推理消耗和结构截断；“模型为了同时生成许多记录而过度推理”仍是解释假设。减少输入没有单独验证输出规模的因果作用。响应中的model仅为deepseek-flash，未提供不可变版本号，前后比较也要披露模型服务版本可能漂移。

## 官方与开源方案

| 来源 | 已核实的机制 | 本项目采用方式与限制 |
|---|---|---|
| [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) | 支持low/high/max；medium映射为high；思考模式下temperature不生效 | 本地model_client仍只允许high/max。先开放显式low配置，仅实验解释阶段使用，保持核验强度。low的任务质量必须实测 |
| [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) | max_tokens约束生成长度；length可能截断JSON；JSON模式也可能返回空白内容 | 不把JSON模式当完整输出保证。保留现有结构校验，记录finish_reason、reasoning_tokens、completion_tokens、有效正文长度。官方虽允许更大上限，本轮不直接升到64K以上 |
| [Google LangExtract](https://github.com/google/langextract) | 长文采用分块、并行、多轮提取，并将结果定位到原文 | 复用原始发言ID和有界子任务思想；不照搬固定字符切块或默认多轮重抽。会议承诺可能由远处回应、改口和取消决定 |
| [LangGraph工作流](https://docs.langchain.com/oss/python/langgraph/workflows-agents) | 拆分子任务、独立工作节点、汇总输出 | 复用本地run_stage持久化节点；无需迁移框架。批次先串行，便于控制费用和失败续跑 |
| [DocETL Gather](https://ucbepic.github.io/docetl/operators/gather/) | 给分块补充前后文及文档结构 | 第一版分批仍保留全文，分的是输出责任范围，避免仅靠局部窗口丢失后续取消 |
| [DocETL Resolve](https://ucbepic.github.io/docetl/operators/resolve/) | 将重复实体识别与归并单列，支持先筛选候选比较对 | 借鉴“提取后单独解决重复”的分工。实体相同不代表任务相同，不能按共同负责人/项目直接合并工作 |

上述资料支持机制选型，不证明本项目移植后能达到某个召回率。分批保留全文会增加累计输入成本，不能承诺更便宜。

## 第一阶段：低推理强度的最小验证

只扩展DeepSeek参数校验以接受low，不更改默认high，也不改变任务分类、标签、引用协议或核验规则。先通过模拟请求验证传参和缓存隔离；medium不作为降低强度的替代值。

用GN29和GN25最近一次已验证的完整tracking结果，固定原文、history、ledger、解释提示及输出契约。解释首次直接用low、32,768生成上限，与已有high的32K尝试比较，避免已知易耗尽的16K前置请求。这是一次受控解释实验，不能称为全链路重新生成。两例均复用各自最近一次ledger，复用范围在manifest逐项列明，不能沿用会顺便冻结facts/decisions却未披露的旧辅助入口。

先跑GN29：若low仍length，停止这一实验分支，进入分批方案；若接口拒绝low，记录能力不匹配，不能静默改回high继续花费。若结构通过，运行现有独立核对与必要的有界修复，再走现有任务归并/SQLite落地入口。GN25随后验证任务保留。核验阶段仍使用原high设置。

本阶段整个实验最多8次新HTTP请求，包括传输重试、引用补丁和核验修复；每次调用最多32K，引用补丁沿用8K。实验入口在实际网络发送前持久化请求额度，恢复不能重新获得8次额度。累计输入/输出与未知用量分别记账，8次限制不是费用金额保证。到顶即记录未完成，不重跑整场、不自动切换更大预算或其他模型。

判定分开进行：

- 技术门槛：完整JSON、引用有效、线程完整、核对完成且可以经现有入口落地；失败节点没有被伪装为成功。
- 任务目标：GN29为8/8必需目标，GN25为3/3，新增FP为0；沿用冻结匹配口径，识别与完整字段另报。条件任务应保留条件，不能提前变成无条件执行。
- low完成但漏任务：承认技术阻塞缓解、任务门槛未过。先定位遗漏发生在解释、核验还是归并；不因为召回不足就直接认定分批有用，不逐例补语义提示。
- 两例全部通过：保留显式实验配置，不立即全局替换high或启动分批重构。后续只补一个既有相邻正例，再决定是否扩大验证范围。这两例已是回归集，不能据此宣称泛化。

## 第二阶段：生成规模仍阻塞时的分批方案

### 输出按线程分批，上下文保留全文

新增batch manifest，固定原文、history、ledger、提示与配置摘要。按线程首次出现顺序稳定分组，每批最多4个线程、累计最多8条update；一个线程的所有update不可拆开，单个超限线程独占一批。两个上限是首轮工程参数，不是官方推荐值或经过验证的最优值。GN29需离线生成实际清单后才确定请求数，不按金标任务分组。

每批获得全文、全局实体及线程只读索引、目标线程的完整更新和候选。它只能产出目标线程的records/events，允许在证据中引用全文任意原始ID。任务涉及其他线程时记录cross_batch_links，不能写入另一批的任务。共同实体仅提示相关性，不作为强制连通分组依据；否则同一教授或项目会把整场重新连成一个大批。

程序按batch_id和批内合法局部ID分配全局record/event ID，同时重写引用；不靠描述文本猜身份。批内校验只要求覆盖自己的线程；合并后再验证全部线程、ID唯一及记录/事件关系。未关联实体仅在全局补齐一次，避免现有context-v5实体补齐逻辑每批重复执行。

### 核验也要限定输出范围

批次解释成功后，逐批核验记录和事件字段；全文及其他批结果作为只读上下文。现有check_work同时输出字段判断和coverage_findings，需拆开这两个职责，不能假设一次完整核验不会成为下一个输出瓶颈。

最后运行一次全局核对：输入全文与汇总记录，只输出遗漏、重复、冲突、跨批关联的差异，不再重写所有records/events。全局检查不能只查“没有被引用的发言”，因为同一句可能同时包含背景和另一项遗漏任务。ledger全覆盖是结构条件，不是全文任务召回保证。

全局差异转成明确target_record_ids或带证据的新候选，复用一次有界repair/recheck。重复项必须经证据核验后明确归并，任务内容、条件、负责人及时间信息保留；不同任务即使同一负责人也必须分开。仍有未解决冲突或失败批次时，保存草稿与未完成范围，不能把完整会议标成成功，也不能提前执行可能被后文取消的任务。

### 恢复与成本

每批与全局核对都是现有run_stage节点；接受结果按输入、目标线程、提示、推理配置与代码摘要复用。批次状态另存，进程重启只续未完成节点，已成功批次不重新计费。恢复不能重置总请求额度。

第一版不递归拆批，不自动叠加多轮提取。单线程批仍耗尽时明确报告该线程未完成，保留现场再决定是否改变协议。解释批保持high、16K→32K，便于隔离“分批”这一变量；若第一阶段low已证明质量可靠但仅最大样例仍截断，可另行明确采用low，不能混着比较。

设批数为B，实验HTTP上限为4B+8：每批解释/核验各预留至多2次，另外8次共用于全局核对、必要修复、引用补丁及传输异常。实际仍服从各节点更严格的上限。首轮仅GN29；通过后再GN25。不自动从第一阶段跑到第二阶段付费实验，必须先形成带实际批数与成本估计的执行清单。

## 不优先采用的路径

直接增加到64K或更高能提供空间，但没有约束每场生成量，也没有解决GN25任务遗漏；暂列诊断后备。续写截断JSON需要可靠身份和合并协议，当前不能安全拼接后发布。关闭思考、换模型、多轮投票同时改变质量或成本，暂不与本轮变量混用。迁移整个LangGraph/LangExtract/DocETL框架也不是本项目必要条件。
