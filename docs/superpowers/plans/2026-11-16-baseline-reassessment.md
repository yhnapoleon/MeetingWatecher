# 统一复评与独立工作发现实验计划

> **For agentic workers:** Use superpowers:executing-plans for execution in this session. 本计划记录用户已授权的复评和小范围机制验证；不晋级生产策略。

**Goal:** 明确已有版本在相同 M1/M2 标准下的表现，验证 A 正常入口，并判断独立原文工作发现能否补回真正遗漏。

**Architecture:** 离线读取历史产物，复用 v4 的 full_flow_checks。实验沿用 A 的检查、一次修正与再核验，仅给实验 D 增加一份不看 ledger/records/events 的原文工作清单，检查阶段对齐清单与现有记录。分类最终仍由原核验/修正协议裁定，来源清单不能直接生成平台任务。

**Tech Stack:** Python 标准库、现有 deepseek-flash 配置、本地 SQLite 模拟器。

**Spec:** [HANDOVER.md](../../HANDOVER.md)，用户已批准依该交接的建议推进。

## 约束与判断边界

- 历史目录、标签、fixtures、默认 split-v3 及生产源码保持原值；所有新增产物放在 runs/2026-11-16-baseline-reassessment。
- 离线复评继承已记录的数据库/权限/幂等检查，仅重新计算 M1/M2 新增检查，不声称重新执行历史程序。
- A 正常入口用实验中的受控适配替换 context-v3 Pipeline 类，实际经过 Extractor、Service、SQLite；记录 A 配置摘要与调用阶段证明适配生效。
- D 是研究原型。来源阶段只收原文、授权任务历史和 Q 证据目录；不收旧分类、标签或预期答案。沿用核验推理配置，无恢复重试。
- 新 A/D 同批比较四例（M2、落实正例、已有第二工作、遗漏第二工作），各两轮。源清单在相同原文的两种 G 输入之间复用，避免来源随机性混淆对齐差异。
- 成功条件：遗漏工作补回，决定不多产任务，已有第二工作不重复，明确落实不丢失；最终内容/负责人/期限/承接/旧任务更新及额外问题均检查。阶段结构成功不计语义成功。
- 若 D 任一门槛失败，记录原因并停止扩大，不堆新阶段。A 正常入口两类各两轮；失败仍记分。
- C23 单独对原文做不看旧标签的复核，随后比较现有标签；标签争议与模型错误分列，不改分。

## 取舍
