# Context-v5：语义核验、预算与失败恢复的实施结果

本次为会议纪要和任务提取增加了命题核验、工作资格检查、首检异议跟踪与有界技术恢复。用户可以在部分模型阶段失败时继续获得独立通过的事实或决策，未通过的工作不会执行。默认策略仍为 `split-v3`，这些能力接入可选的 `context-v5`。

**定向验收共 20 例：12 例通过原文复核，5 例仍有语义错误，3 例未完整完成。** 自动契约通过 15/20，因此不能用自动分数宣称这些问题已全部解决。用户在补充接口余额后明确要求只跑必要测试，本次取消原计划中的 95 场景×2 轮全量回归，使用 12 个原失败场景和 8 个冻结正反例，各一轮；空对象接口适配后仅补跑受影响的 C20、SV17、SV19。

## 从一个具体错误看系统原因

C20 原文是“我们会把这个视频剪辑，然后给大家确认，然后还有这个文稿”。早期输出把它概括为“同时处理文稿”，纪要检查又把自己的概括当成原文依据，判为 supported。工作分支也可能预设文稿需要处理，再向用户询问处理动作。

这个错误存在于两个独立出口：工作结果经过检查，facts/unresolved 原先却直接展示；两者还可能共享同一种错误前提。新增检查补齐了出口，但仍会出现候选描述影响判断、引用层级丢失、角色错配和真实未知漏提。C20 的最终新运行只保留“同时还有文稿”，工作候选仅询问视频工作的负责人；然而冻结阶段重放仍观察到文稿被误判为工作，不能把一次正确结果视为稳定解决。

原 10 次未决错误也不能合并为一个“全部删除未决”的规则：C09 的研究对象已经回答，P05a/P05b/P06a 的引用问题未被本场采用，C13 是已接受的产品结果回顾；P08b 则有真正的能力未知，只应纠正调查者、能力主体和调查对象。标注审计保留这些区别，并冻结了 6 个原场景的命题标准和 20 个新输入；这些标准由助手依据源材料编写，不是独立人工金标。

## 已实施的机制

| 问题 | 实施方式 | 当前验证边界 |
|---|---|---|
| HT04 的缺口与追问不一致 | 在归约时先确定已完成报告和旧任务关联缺口，再生成问题；不再事后删掉 commitment 却留下旧问题 | 离线旧结果重放及新正常入口均只问关联哪条旧任务，未误改两条旧任务 |
| 首检正确、修正未改、复检反转 | 程序为实际异议绑定固定 ID；repair/recheck 必须携带原异议，逐项 resolved、overturned 或 unresolved；允许依据原话推翻错误首检 | 已覆盖遗漏异议、未解决异议、合理推翻；无法保证模型对原话的裁定本身正确 |
| 纯提及或备选方案成为工作 | 工作检查增加 speech_scope、work_basis、证据及本场采用依据；分类冲突进入修正，不能预设动作再补负责人/承接缺口 | C20 最新正常入口正确；C11/C24 仍能在资格判断本身出错 |
| facts/unresolved 缺少核验 | 逐命题检查主体、动作、对象、话语范围及最终状态；改写和补漏进入一次修正、独立复检；原候选和异议留痕 | P05a 等引用问题已纠正；P08b 角色错误和 SV15 漏提真实未知仍未解决 |
| 暂缓事实依赖工作成功 | 纪要分支独立保留暂缓事实；只有经核验、同版本的显式记录关联才能在展示时去重 | SV17 工作失败时，暂缓到下周的事实仍可见，没有创建任务或立即追问 |
| 推理耗尽 | 同逻辑节点保留完整输入，16K 的 length 只升级到 32K 一次；预算只记在 attempt，不重置已接受祖先或尝试上限 | CP01 两预算各 3 次均完成，不能证明 32K 提升成功率 |
| 格式、网络及中断 | 每节点最多首发＋一次恢复；保存 request/response/meta/attempt，完整校验后原子接受；断流、冷却、终止错误及崩溃状态可恢复 | 离线覆盖损坏 accepted、断电窗口、usage 回填、402 终止和 429 冷却；真实格式恢复仍可能耗尽 |

纪要核验失败会将 facts/unresolved 标为失败；工作和决策按原依赖组独立处理。正常 Service 入口测试确认：已承接调查、真实能力未知和非空决策能够并存；纪要耗尽时任务和决策仍提交；重复 process 不重复请求已成功阶段或重复写任务/决策。系统判断失败不会被改写成让用户回答模型猜测的问题。

## 失败恢复的实测与调整

### 预算对照

CP01 使用历史失败的同一前 8 段请求，固定 prompt、输入和 high 档位，仅改变输出预算，各运行 3 次，探针不自动重试。

| 预算 | 完整追踪校验 | 平均输出 token | 平均耗时 |
|---|---:|---:|---:|
| 16,384 | 3/3 | 8,519.7 | 49.866 秒 |
| 32,768 | 3/3 | 11,909.0 | 69.242 秒 |

一份 32K 响应用了 18,191 输出 token，说明该额度确实可用；但六次采样均通过，样本不足以估计可靠性收益。最终仍采用 16K 首发、仅 length 时一次 32K 恢复。完整 CP01 新运行读到了后两段澄清，任务范围正确；纪要又将“开关名称未统一”的背景升成当前未决，最终语义复核仍判失败。该项是依据既有产品政策追加的原文复核发现，不是预冻结的 CP01 逐命题金标。

### 格式恢复

C14 固定历史成功首 ledger 与失败第二输入，带回非法 JSON 的三次普通反馈重生成全部失败。C11/C14 的配对探针显示：保留非法原文会重复错误结构；只给错误定位时两例都可解析，但 C11 仍将 checks 放进 record_checks，实际完整校验失败。生产语法恢复因此不再回送非法文本；schema/evidence 错误仍可携带已解析候选供修正。

随后对 C14/C11/C09 做了三个 Beta strict 工具实验，三例都通过原本地完整协议。它与 JSON content 模式是不同的接口：强制唯一工具时关闭 thinking，保留预算、原始本地 schema、身份和证据校验。只有官方 DeepSeek HTTPS 端点自动启用；自定义代理保持原 JSON 恢复，避免改错路由。官方说明见 [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/) 和 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。

后续正常入口暴露了两个重要限制：

- 严格接口拒绝空 object。C20/SV17/SV19 的合法空 checks 因此返回 400。适配层从工具 schema 中省略程序可确定的固定空对象，返回后仅补回缺失的固定字段，再执行原完整校验。已有错误值不会被覆盖。真实 C20 冻结请求验证了接口接受和原契约通过；该次响应主动包含了 checks={}，缺字段回填本身由离线测试验证。
- 实际 strict 响应仍出现错嵌字段或非法 arguments：C14 的 checks 层级错误、最新 SV17 的 JSON 语法错误均被本地校验拒绝。**strict 不是取消本地校验或保证恢复成功的依据。** 两次耗尽后保持 partial，不增加第三次请求，也不自动补括号采纳结果。

429 优先遵守 Retry-After；无明确等待信息时采用冷却。等待超过单次短等待上限时持久化 deferred，不消耗第二次尝试，后续重入再检查时间。402 等终止错误不自动重试。断电后从已写入 meta 恢复冷却和终止状态；已收到 response 的 usage 也会恢复，缺失用量单列未知。

## 定向验收结果

最终表使用各场景最后一个对应代码版本的结果，先前失败全部保留。C20/SV17/SV19 的补跑是修复接口兼容问题后的验证，不是反复抽样取最好结果。

| 分类 | 场景 | 结论 |
|---|---|---|
| 原失败场景通过 | C09、C13、C20、HT04、P05a、P05b、P06a | 原文、纪要和工作结果符合本次口径 |
| 新对照通过 | SV02、SV09、SV10、SV16、SV19 | 覆盖引用被本场采用、仅提文稿/明确并列工作、调查启动条件及当前目标需求 |
| 仍有语义错误 | C11、C24、P08b、CP01、SV15 | 产品备选或转述被升为工作；角色/对象错误；背景升为未决；真实能力未知漏提 |
| 未完整完成 | C14、SV17、SV05 | 前两例技术恢复耗尽；SV05 纪要正确，但工作解释仍为 interpretation_unresolved |

8 个新对照中，冻结要求的 6 条真实未决保留了 5 条（5/6）；唯一漏项是 SV15：调查已承接，“资料是否支持离线检索”只留在 facts，unresolved 为空。新对照未发现无依据未决新增。旧场景另发现 4 条无依据命题：C24 两条、P08b 一条录像对象未知、CP01 一条背景问题；不把它们混入新集召回分母。

C14/SV17 的 partial 与语义失败分开报告；SV05 虽然 Service 状态为 processed，仍不视为完整语义通过。旧 172/190 来自不同范围和复核口径，本次 12/20 不能与其直接比较。只做了一轮定向验收，不能据此声称稳定性或总体准确率提升。

## 尚未解决的问题与下一步判断

现有机制能检查协议和模型判断之间的矛盾，却不能保证模型把“产品选项”正确标为 option，或把连续转述正确标为 quoted。首检错误时，固定异议机制没有异议可追踪；复检也可能用同样的错误解释将异议标为 resolved。C11、C24 和 C20 冻结重放已经提供了具体证据。

对 C20/C24 追加“逐谓语核对、继承引用框架”的提示未消除错误；单独将纪要检查切为 high/16K 也未修复这两例。因此没有采用这两个额外成本方案。后续语义实验应先针对源句的引用范围、主体和动作建立独立判定，再核对候选；用 C11/C24/P08b/SV15 与相邻正例比较，验证它是否真正降低相同解释被重复认可的概率。当前证据不足以升级默认策略。

后续按用户要求默认使用失败定向＋代表性正反例。只有改动影响面和失败证据要求时才扩大范围；不默认跑 95×2，也不通过多次重跑挑出成功结果。
