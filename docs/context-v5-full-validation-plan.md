# context-v5 全量回归计划

2026-11-16，用户明确要求开跑。固定当前算法和模型提示，执行两轮完整回归；不在两轮之间调参或修复算法。

## 范围

每轮95个场景：原综合集54个（corpus 30、context 1、probes 8、cancellation 2、updates 13），边界对照33个，专项补充6个，完整M1→M2流程2个。共190次场景执行，4个并发worker。每个场景使用独立输出目录、模型记录和SQLite数据库。只有一次原有的语义修正机会；不进行自动网络/格式重试，不使用历史模型缓存，不冻结模型阶段。

补充集包括C23明确目的与无关背景、无日期工作、暂缓后推进、同段范围调整与发送测试结果、M1待定事项收集。两个完整流程分别为原始M2与明确配置测试正例。

## 评分迁移

- M2必须有范围调整候选，保留两个开放对象与今天，只确认个人负责人；旧任务完成且不新增自动写入任务。
- C23核心是会后联系袁校长并继续沟通，推断的补问目的不再必写；原标签保留，新标签只进入本次manifest。
- 待定事项不混入执行任务或即时追问；无日期工作仍保留。
- repair失败、解释未解决、提取错误与首次请求失败计入分母，不能因最终items为空而算正确。
- 仅数量和字段检查不代表语义正确。逐项对照原文核对动作、对象、目的、归属、时间与追问，另存绑定输出哈希的源文复核。
- P03a/P12a仍按“陈述决定/当前范围值”保留旧边界对照；与M2的“今天改一下”执行指令区别已在运行前声明。若原文存在竞争理解，在复核中单列争议，不根据新输出悄悄改标签。

## 指标

按组报告自动契约通过与原文复核后的通过，分开记录任务遗漏/误建、内容/归属/时间错误、多余追问、修正与协议失败；汇总调用量、token、延迟、两轮一致性。语料中的dev/holdout此前已被查看，本轮属于回归，不称为盲测。需要比较历史版本时，先按当前标准重评，不能直接引用旧总分。
