# 工作边界、字段缺口与问题关闭

2026-11-14。用户已认可前置判断能力优先，授权依次调研、设计并修复。本轮沿用本地 Python/SQLite 和 context-v1；默认 split-v3 不变。

## 调研与证据

事件共指研究将事件理解为动作、参与者、时间和场景的组合，提及分布在多句中，不能仅按共同实体合并：[Yang et al., TACL 2015](https://aclanthology.org/Q15-1037/)。本项目借鉴身份判断，不部署该论文的聚类模型。

[Purver et al., 2007](https://aclanthology.org/2007.sigdial-1.4/)将行动项放在提出、讨论、分派和承诺的互动中分析，支持分开判断工作内容和承接。[SOM-DST, ACL 2020](https://aclanthology.org/2020.acl-main.53/)先判断每个槽位应保留、删除或更新，再生成变更值，支持局部更新而非全条重判。[Clarify When Necessary, 2025](https://aclanthology.org/2025.findings-naacl.306/)研究何时应该澄清；本轮把无效追问计为失败。这些文献提供设计依据，效果以本项目记录检验。

旧输出中：C20 的视频和未知文稿被合并；C21 的篇幅背景成为范围阻断；CP03 已回答的活动决策仍被评为新工作；CP05 因跟踪提示只保存理解工作需要的对象而跳过纯实体。record_checks 只提供总体 verdict，代码没有办法分清内容不成立与承接/问题表述不对。

## 方案选择

仅补提示成本最低，但不能让代码区分核验失败字段，也没有已解决问题类型。新建独立工作聚类模型或知识图谱会增加数据和调用负担，当前证据不足。本轮选择局部协议修复：工作边界主要在跟踪/解释时判断；核验显式给出失败字段；已解决问题有独立类型。继续保存原话，不根据词相近、引文重叠做自动合并。

## 按顺序实现

1. **工作边界**：以可分别决定/执行的动作和对象分工作。未知并列材料单独保留；同一动作的必要目的/范围不拆成第二项任务；约束附在其工作上，背景不自动成为必须确认范围。跟踪提示保留无动作但被明确讨论的实体。先检验 C20、C21、CP04，并用“同一工作后续补范围”作反例，避免过拆。
2. **字段分别判断**：record_checks 的非 supported 结果必须给 `issues`（work/classification/reference/scope/owner/commitment/time/relation/state/question）。只有 owner/commitment/question 出问题且已有事件内容与时间受支持时，可保留可靠工作描述；负责人或承接疑点仍阻止自动执行。内容、分类、时间、关系问题继续阻断。assigned 的核验是判断“确实分派过”，不是要求本人已经接受。不修改旧 evidence-v1 的 reducer。
3. **问题关闭**：增加 `resolved` 类别，表示核对/选择/提问已在会上解决，证据需包含原问题及后文答案；与已完成旧任务不同，旧任务完成仍经 event 更新。withdrawn 表示取消。已有完整记录的核验分歧只写该记录，uncovered_spans 只用于未被任何记录涵盖的新工作，避免一项问题复制成多张卡。取消仅关闭指向同一活动且失去执行条件的安排；善后工作及其他活动保留。

## 验收与边界

程序测试先失败再修复：并列模糊记录不挡明确工作；真正范围缺口不被放行；owner/commitment/question 的核验疑点不污染已支持内容且不绕过执行规则；resolved 需有依据且不追问；旧任务完成继续更新。通过后从正常评测入口运行既有六例、连续窗口和中文八例，旧语义标签与行为契约不变。另冻结前置能力准则，包含取消后追问、重复卡片、约束误拆。失败调用记录首次结果，至多同配置恢复一次，不对成功语义输出重采样。
