# 公开会议语料取样与证据检索实验

调研问题是：没有内部会议时，今天能拿什么开始标注？本次直接读取了中文 VCSum 开发集、阿里官方行动项解析代码与提交格式样例，以及英文 QMSum 同一系列四场会议。下文的计数来自指定版本。没有把第三方逐字稿复制到项目中。

### 一个能立即用于标注讨论的反例

VCSum 的 `65_0`，发言组 1、句 4（均从 0 开始），主持人预告稍后会向现场老师提问。说话人明确，表述也是将来时，但动作将在会议内发生，没人承诺会后交付。按本项目口径应标“会内安排”，预期新增任务数为 0。另一处 `198_4` 的发言组 10、句 2 包含“我们负责人”，朴素规则查找“我们负责”也会命中。它解释了为什么第一轮要为负例保留触发原文和未建原因。[原始片段](https://github.com/hahahawu/VCSum/blob/8e51d72e4e6f3af4074fd5b260b6f6d2e75e86c7/vcsum_data/short_dev.txt)

在上述 135 个片段中，按句搜索 `我来负责|我们会在|我会在|我来做|我来讲|我负责|我们负责|交给|我来回答|接下来我` 命中 23 句。这是关键词取样的规模；没有人工遍历所有正例，所以不能用 23 推算任务密度、准确率或召回率。

## 英文：在同一项目的四场会里检索证据，会错在哪里？

取 QMSum 官方 test 中 ES2004a–d 的具体问题。四场分别有 320、528、604、756 段发言，每场 4 个不同说话人标签，共 29 个带证据的问题，其中 5 个需要多个不连续区间。原文件以发言段编号标注证据，字段是字符串形式的起止下标。一般性问题缺少相同的区间标注，未计入本实验。[数据与论文](https://github.com/Yale-LILY/QMSum/tree/83d7768c1f2b4dfeb091385d3dc7e239b8e5bb7e/data/ALL/test) · [QMSum](https://aclanthology.org/2021.naacl-main.472/)

**实验条件。** 使用 16 段发言的窗口，步长 8，尾部截断，合计 273 个窗口。英文正文小写后按字母数字切词，BM25 取 k1=1.2、b=0.75。问题去重词频，不使用摘要、答案或说话人身份。固定四场文档频率和窗口得分，只切换可检索候选范围，避免把分词或权重变化混入范围对照。并列按会议和窗口原顺序选择。只取排名第一的窗口。

| 候选范围 | 第一窗口位于正确会议 | 至少碰到一段人工证据 | 平均覆盖人工证据段 | 第一窗口中人工证据段平均占比 |
| --- | ---: | ---: | ---: | ---: |
| 预先给定正确会议 | 29/29（范围保证） | 14/29 | 20.22% | 26.72% |
| 限本场及此前场次 | 25/29 | 12/29 | 18.50% | 20.91% |
| 四场系列均参与 | 22/29 | 12/29 | 18.50% | 20.91% |

后三列先对每个问题计算，再按问题汇总。后两行的命中数相同，但开放后续会议又带来 3 次串会。范围受限行的全局词频仍由四场估计，它用于比较候选范围；正式在线回放需要按查询时点重建索引统计。官方题目面向单场会，我们人为加入同系列会议作为干扰，测到的是定位原证据的能力。这个小切片无法评估中文模型效果、权限隔离或决策关系的准确率。

**错例与设计含义。** ES2004a 的第二个具体问题问团队为什么决定采用菜单显示。人工证据分布在段 203–232 和 246–248。第一窗口取到 216–231，16 段全在正确范围，仍只覆盖 33 个证据段中的 16 个。ES2004c 的第三问追问设备实际包含哪些零件，正确依据是 64 和 197–202；已知正确会议时首窗落在 32–47，四场检索时又串到 ES2004b。第一例该试多窗口证据合并，第二例该分别测会议选择和会内定位。对飞书评测，单报“至少命中一段”会掩盖这两类失败。[ES2004a](https://github.com/Yale-LILY/QMSum/blob/83d7768c1f2b4dfeb091385d3dc7e239b8e5bb7e/data/ALL/test/ES2004a.json) · [ES2004c](https://github.com/Yale-LILY/QMSum/blob/83d7768c1f2b4dfeb091385d3dc7e239b8e5bb7e/data/ALL/test/ES2004c.json)

**复现。** 在本项目目录执行以下命令。Python 3.10+ 标准库即可。首次读取固定提交的四个 JSON，后续使用本地缓存。输出包括 SHA-256、分组计数和逐问题的会议、窗口与覆盖率。测试文件已在这次探索中查看；后续围绕这些错例调参时，应按系列另留验证材料。

```powershell
python scripts/probe_qmsum.py --cache "$env:TEMP/feishu-eval-qmsum"
```

## 第一批标注如何取样

建议先填一张覆盖表，每个格子至少找一个能判定的样例。四个优先格子是“甲提议、乙认领”“说了将来时但属于会内安排”“会前已完与会上才报告完成”“同一事项对两个查看人分别可见和不可见”。第一类优先来自 MUG 或自然录制，第二类已有上述可定位负例，后两类用自录系列及平台快照。采集表另记缺失字段、来源、许可和复核状态。后续扩大样本时同时保留随机整场会议，以免刻意挑难例造成的错误率被当作线上错误率。
