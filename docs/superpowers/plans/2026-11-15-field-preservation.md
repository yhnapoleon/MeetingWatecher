# 字段缺口不丢工作：修改与检验计划

> 执行方式：按 executing-plans 在本会话实施，完成后独立代码审查。用户已授权方案及检验，不重复请求同范围许可。

**Goal:** 明确工作不因可选日期或承接疑点消失，未确认字段不自动执行。

**Architecture:** context-v1 专用的新工作处理函数分别处理字段疑点，旧 evidence reducer 保持。模型提示纠偏与程序机制对照分开，遗漏修正先做隔离实验。

**Tech Stack:** Python 标准库、SQLite、现有模型客户端。

**Spec:** [设计与调研](../../field-preservation-design.md)。

## 约束与审查重点

- 默认 split-v3 不变；不放宽身份、权限、来源或受众规则。
- 重点反例：缺日历日期、两期限未定、错误时间混入标题、另一人的回应、建议没有接受、目的从背景推断。
- 不因“无日期”删任务；不因“保留任务”把有疑问的日期/承诺执行。
- 无 Git，使用快照；保留旧标签及首次失败，合成场景不称盲测。
