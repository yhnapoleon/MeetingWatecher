# 会中纪要逐步形成：实现与验证

用户指出，供电讨论的完整摘要和三张卡片同时出现，无法体现内容随会议逐步形成。本轮将真实 AI 视图改为基于新增发言维护议题卡：先记录问题，后续理由与倾向到达后更新原卡；新议题才创建新卡。每张卡保留各版内容、处理到的发言时间和原话引用。

## 输入与更新

后端按照当前播放游标释放已经结束的 STT 稳定片段。累计约 12 秒后选择下一段可处理边界；模型繁忙或晚打开视图时，也按连续的小窗口补齐，不把积压内容一次合成最终纪要。临近结束时不足 12 秒的尾段会单独处理。没有新转写时不调用模型；同一场只允许一轮增量任务在途。

每轮输入包括本次新增发言、短的前文衔接、已记录议题和仍被引用的历史原话，以及任务状态。生成端输出 `summary_changes`：新议题的 ID 由服务端分配，同一议题必须引用已有 ID；更新内容必须有至少一条本次新增发言作为依据。只有旧引用的改写、未知卡片 ID 和未来引用不能成为更新。

后端验证通过并保存后，界面立即呈现本轮变化。这里是按发言窗口增量更新，不是逐字流式输出；实际呈现时间仍包含转写稳定等待、轮询和模型处理时间。没有把完整答案拆开定时播放，也没有把历史预设事件当模型结果。

## 界面与行动项

- 议题卡保留稳定 React key，同一话题补充、纠正时不重建 DOM。卡片显示开始记录时间、最近更新时间和版次，可展开查看逐步形成过程。
- 讨论脉络按议题新增节点；普通补充只增加该议题版次，不再每次模型返回都增加一个节点。
- 自动分工只从新增发言提取。新增工作创建待确认卡；后续补充同一待确认事项时复用 ID，字段和证据保留历史版本。查看早期游标仍得到早期字段。
- 多人分工如果出现在同一个稳定转写窗口，可以在同轮出现；不人为将同时获取的结果错开来制造动态效果。
- 用户确认仍通过已有 WorkLedger / Service 写入本地任务模拟器。没有明确截止日期的工作不推断 DDL。
- 文字问答、会中补课、方案比较与交付材料保持按需请求、完成后展示；它们与持续更新的会中纪要不同。本轮没有为这些结果添加模拟打字或虚假流式效果。

每次刷新只读取当前会议最新的完整议题状态，展开的修订过程包含在该状态中。助手任务列表不再轮询全部摘要快照，避免更新频率增加后不断传输整段历史。切换会议独立订阅；倒退游标时立即隐藏后续状态。已存在的旧式归档仍可阅读，并标为“历史整段纪要”。

## 验证范围

离线 Copilot 测试共 29 项通过，其中新增 8 项覆盖：逐段推进、稳定 ID、无新事实不增卡、引用必须来自新增发言、候选字段补充与旧范围可见性、保存恢复、会末尾段、同一轮不重复排队、摘要查询与助手历史分开。前端原有 15 项测试、Sites 4 项检查、类型检查及构建通过。

真实模型验证包括正常速度连续浏览器播放，以及第一场后续分工和第二场起始讨论的 API 连续增量处理。浏览器记录每次变化的素材游标、处理边界、卡片 ID / 版次，检查已有卡片没有重新挂载；各轮返回的证据结束时间均不得晚于处理边界。具体运行证据索引见 `evidence/incremental-summary-2026-11-23.json`。

首次试跑中，模型在转入功能讨论时曾仅改写旧的供电卡。新增证据校验拒绝了该轮，未将它显示为新进展。随后将本次新增发言独立成 `new_transcript`，减少未引用历史，并明确按已有卡片判断重复；继续实测已生成新功能议题。失败日志保存在 `runs/copilot-incremental-v1`，没有覆盖。

第一场后续验证中，先出现项目经理整理纪要的候选，再出现 David / Craig / Andrew 的三项分工；各负责人各一项。David 的候选经确认保存后，在第二场仍以同一 GUID 可见。此验证是本轮产品路径检查，不计入既有 115 场景的离线评测指标。

旧 8:42 双入口片仍反映上一版整批摘要机制；本轮另提供正常速度的增量实测片段，尚未将完整双场成片重新剪辑。所有旧片、原始帧和调用记录保留。

核心代码为 `meeting_copilot/live_summary.py`（窗口、上下文与合并）、`jobs.py` / `api.py`（运行与查询）、`work.py`（候选版本）及 `demo/src/copilot/LiveSummary.tsx`（稳定卡片与订阅）。

在项目根目录运行：

```powershell
$env:PYTHONUTF8='1'

```

前端在 `demo` 目录运行 `npm run typecheck`、`npm test`、`npm run test:sites`、`npm run build`。真实浏览器验收脚本为 `demo/scripts/video/check_incremental.py`，通过本地 4193 正常进入会议并连续播放；后续分工/API 验证脚本为 `demo/scripts/check_incremental_continuation.py`。二者会调用配置好的真实模型，需要按各脚本使用独立数据目录及不重复的输出目录。

## 行动事项动态镜头补充（2026-11-23）

用户强调动态生成行动事项是演示重点。行动事项页增加同屏概览：从空列表开始，候选随真实模型返回加入；概览显示负责人、工作、对象、DDL 和原话时间要求，点击进入完整字段及确认操作。候选与已确认任务仍分开。

补录时发现有效新行动项被同轮无新增依据的旧纪要改写牵连：原逻辑拒绝整轮，导致新任务无法出现。现对“已有卡片、只有旧引用”的重复改写保留原卡并记录 `ignored_changes`，有本次新增发言依据的行动项继续生成；未知议题 ID、越界引用和缺乏新增依据的新任务仍不能通过。新增回归测试检查旧卡不变、新任务字段能继续补充，Copilot 测试增至 30 项。

正式动态任务片从本场 03:10 开始。此前背景复用真实模型已经生成的结果，录制开始时任务与候选均为空；分工段在录制中调用模型，不预先加载任务结果。视频保持会议与行动事项区同屏，先看候选到达，再看详细信息、原话与确认保存。同一稳定片段内的三人分工在同轮出现，不人为错开。

第一轮失败记录在 `runs/copilot-live-actions-v1` / `demo/videos/live-actions-20261123-v1`，保留用于追溯；第二轮使用独立数据目录 `runs/copilot-live-actions-v2`，只复用第一轮 190 秒前的 9 个真实背景窗口及原始日志。播放后的所有分工处理重新调用模型。


## v4 双场彩排中的任务进展修正（2026-11-23）

首场从空任务表录到三人分工、自动候选和文字核对后，第二场真实彩排发现三类问题。第一类是模型将研究汇报只写入纪要，未输出进展；生成提示现分别要求检查已确认任务的新进展和新分工，研究方法、发现可关联原任务，不必再次承诺。用漏掉的 Andrew 原始输入复测后，返回了正确目标 GUID 和 progress，记录见 `runs/copilot-progress-update-recheck/andrew.json`。

第二类是模型漏填 existing_proposal_id，连续窗口为同一任务重复出进展卡。WorkLedger 现在用明确的 target_guid 和负责人查找已有待确认进展，补充原候选，保留按时间可见的版本。这个匹配只用于已确认任务的精确身份，不按姓名合并内容不同的新任务。新增正常 API 回归用例验证两次更新沿用一个 ID、早期视图不看见后续内容、确认保存最新版本。

第三类发生在 David 开始汇报时：任务对象中带有首场分工证据，但增量上下文的统一 evidence 集合只收录本场卡片及待确认事项引用。模型引用原分工后被校验拒绝。现把当前可见任务的原话纳入同一证据集合并映射短编号，仍单独保留本次 new_transcript / new_evidence_ids；每个进展变化仍须引用本场新增发言。失败调用 `1b80e526-9e49-49a1-8617-8ea9f7db8757` 保留，修复后相同稳定窗口成功处理。

31 项 Copilot 测试通过。真实录制得到三人各一项原任务、两场各一次确认，共 3 项任务和 6 条记录，最终均为进行中；项目经理纪要候选仍待确认。第一场 37 个增量窗口、第二场 39 个增量窗口，引用时间边界及任务身份检查通过。这些是产品路径验证，不替代冻结评测的准确率。Andrew 的任务快照主要记录研究方法；其市场发现另在动态纪要中展示，不宣称任务详情覆盖每条后续发言。

录制脚本会在第二场将更新议题滚入可视范围。首场来自 `progressive-20261123-take2`，第二场采用首场结束检查点继续的 `progressive-20261123-second-take3`，组件段从素材 643.2 秒接续到 `progressive-20261123-tail-take2`；同一组 GUID 贯穿，第二场未预生成。旧失败彩排、原始帧及模型日志保留。最终合成与音轨验收结果另见 `evidence/progressive-demo-2026-11-23.json`。
