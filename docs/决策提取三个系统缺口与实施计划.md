# 决策提取的三个系统缺口与实施计划

## 起点与诊断边界

本计划以方案 1 的最终版为基线。两场开发会议共输出 17 行，按可独立改变的属性拆为 19 个主张。原文严格口径为 14 个正确、5 个错误，精确率 73.7%，AMI 参考召回 10/11。早期基线另有讨论框架措辞争议，后续比较同时报告逐项得失和两种判法。两场最终原始候选均为 effective，程序实际过滤 0 行。显式撤回对照能过滤 withdrawn；因此可定位故障阶段，但单次输出不能解释模型内部为什么作了这个判断。[冻结口径](../runs/2026-11-18-decision-adoption/rubric-before-run.json) · [逐项评分](../runs/2026-11-18-decision-adoption/evaluation.json)

决策阶段当前直接接收完整逐字稿与授权历史决策。decision_output 校验状态、来源及引用 ID，随后把选项、采纳、后文三组证据合并输出。下游纪要核验读取决策作为上下文，写回事实和未决问题。Service 的 supersedes 处理跨会议的同属性替代。最合适的实验接点是**决策原始响应到业务输出之间**，此处还保留证据角色和待选状态。[决策提取](../meeting_eval/extract.py) · [决策存储](../meeting_eval/service.py)

## 1. 结论范围扩大：缺少语义上独立的证据核验

ES2002b 的“高级功能可选”与“必须放在隐藏区域”可以分别成立。项目经理认可了前者，隐藏设计来自另一人的建议。当前一次生成给两者写出同一结论、挑选证据并判为 effective。程序只检验 ID 属于本场。类似情况还发生在把静音纳入产品、把语音识别的开放讨论写成本阶段排除。引用数量对这种错误缺乏区分力；一句来自简报的售价恰恰可能是充分证据。

方案 A：把候选拆成可独立改变的取值和限定。核验方先读相关发言和前后问答，只看议题，不看提取方的状态、理由或置信度，独立写出原话支持的最强结论。程序再把两份结论按对象、取值、范围和确定程度对照，允许保留、缩窄、转待定、拒绝。缩窄后的文字也须绑定采纳证据，不能凭核验新增一项决定。一个批次处理同场多个候选，避免每条重读全文。实验时先给人工核实过的片段测核验上限，再换成自动选取的片段；两者落差揭示证据定位问题。共享同一模型仍可能产生相关错误，用人审裁定效果。

FENICE 将摘要拆成原子事实并与原文对齐，可借鉴其核查粒度。会议还要额外判断回应到底采纳了哪个命题；Fernández 等人的决策对话研究区分议题、可能的解决方案和达成一致，为此提供了标注依据。[FENICE](https://aclanthology.org/2024.findings-acl.841/) · [会议决策对话研究](https://aclanthology.org/W08-0125/)

## 2. 后文改口失联：缺少同一议题在本场内的状态更新

ES2002a 早期多人认同整合设备控制值得考虑，收尾又询问是否仅限电视，答复保持开放。最终候选只引用前期问答，later_ids 为空。即使阶段一的核验读懂了早期局部对话，缺少收尾内容也无法判断散会状态。反过来，一条晚到的疑问也不必然撤销已生效的正式规定。

方案 B：对同一对象和属性，按逐字稿位置收集提出、采纳、限缩、替换、重新开放的发言，分别保留原命题和证据。只有后文确实指向同一命题，且发言具有改变当前安排的含义时才更新；个人追问保留为质疑，正在探索的替代方案与仍有效的旧规可并存。局部调整只更新涉及的限定。程序根据有证据的更新重建最终状态，有歧义保留待定。议题相似度用于寻找候选发言，不能直接触发覆盖。已有任务 tracking 可以提供候选位置，但决策来源仍须回到逐字稿，保持决策分支可独立运行。先用完整稿检索同议题的后续发言，验证定位后再考虑增量缓存。

对话状态跟踪研究把“找出哪一项发生了什么变化”和“写出变化后的值”拆开。该研究的实验对象是任务型对话；这里借鉴更新机制，并用会议中的发言者、采纳对象和异议案例重新验证。AMI 决策总结研究还发现，同一决定的相关发言可能在时间上不相邻。[选择性更新对话状态](https://aclanthology.org/2020.acl-main.53/) · [AMI 决策总结](https://aclanthology.org/W11-0503/)

## 3. 漏项与重复：缺少独立发现候选和判断决策等价的步骤

ES2002b 的“产品要好看且易用”在原文里有主持人复述和其他人回应，原始候选却没有它。同时，“数字选台”既作为单个功能输出，又被列入必备按键集合。前者发生在发现候选时，后者发生在决定输出粒度时。单独增加末端核验无法发现漏项，单靠字符串去重也无法识别集合包含关系。

方案 C 分两项验。C1 先按发言顺序分段，从全文独立列出讨论的属性、既有要求、可能的采纳或修订位置。分段发现不看旧决策清单，再把两个候选集求并，送 A/B 确认。覆盖审计要回答“哪个属性的最终值没有记录”，不能用“这段已引用”代替。C2 对可独立改变的属性归并，记录对象、属性、值、限定和时间。只有同义或已被完整包含且无独立限定时才合并，原始证据取并集。互补方案、不同适用对象、先后改值留给 B；同时保留单项中的独立例外或约束。先试对已有 17 行离线归并，以数字选台的包含关系为正例，以产品分类与讨论方法为防误并反例。QMSum 的定位后总结方法支持分开测量证据定位与总结；对同一决定的非连续发言做聚合也有 AMI 研究依据。[QMSum](https://aclanthology.org/2021.naacl-main.472/) · [决策发言聚合](https://aclanthology.org/W11-0503/)

## 实施顺序与验收

| 阶段 | 工作与实验对照 | 推进依据 |
| --- | --- | --- |
| 0 固定评测 | 沿用 11 项 AMI 参考、已裁定的 19 个主张及原始响应。在看新版输出前，另标部分支持、重开、重复包含和独立例外等边界。保留候选到原文的位置映射。开发用 ES2002a/b；电影会议 IB4011 已经看过，只作回归。另预选一场未用于设计且有决策参考的完整会议作最终验收。 | 同一评分器能复现 14 正确、5 错误、10/11；记录首判有分歧的项目。人工给出的证据位置只用于标注和诊断对照。 |
| 1 独立核验 A | 在 experiments/full-meeting/decision_adoption.py 的实验旁路读取冻结候选及上下文，批量生成逐主张的核验记录。比较同一组候选核验前后差异。 | 隐藏实现被去除或缩窄到有依据的范围；售价等直接宣布的决定保留。报告纠正数、误删数、是否新添细节。若给足证据仍判错，先修核验标准。 |
| 2 状态更新 B | 固定 A，比较只用局部问答与加入同议题后续发言的结果。保留命中的后续段、每次更新及最终状态。涵盖含蓄重开、明确撤回、明确改值、普通追问、无后续变动。 | ES2002a 的多设备方向在散会时保持开放，周四替代周二仍正确，已确定的现行规定不因个人质疑被撤销。分别记录后文未找回、找回但处理错误。 |
| 3 覆盖与归并 C | 固定 A/B。先只加 C1 看候选召回和新增误报，再加 C2 看重复数和误并数。所有新发现的候选走同一套核验及状态更新。 | “好看且易用”以有证据的要求被保留；数字选台只计一次；完整必备功能、独立限定与不同对象均保留。 |
| 4 正常入口 | 表现合格的组合接入 context-v5 决策分支，复用现有节点缓存、有界恢复及失败记录。内部保存变更前后主张和证据，沿用现有对外字段。用 Service 检查存储、纪要、重复提交、跨会替代和“同句有任务又有决定”。 | 对开发两场的建议目标是参考命中 11/11、严格 FP 从 5 降至最多 2，保住原有 10 个 AMI 命中；允许删除重复但要保留其独有内容。再检查独立会议上相对基线的逐项得失和争议口径，不用开发集阈值宣称泛化。 |

每项实验固定输入、历史、模型和采样配置，分别记录候选召回、最终参考召回、按原文裁定的精确率、输出差异、耗时和 token。相关论文验证的是各自任务，这些目标属于本项目建议的验收条件。第一轮仅在两场保存结果上做 A，建议每场一个批次并保留请求级费用记录。若两场均无净纠错，先区分输入证据不足与核验本身失败，再决定投入。若有净纠错，B 和 C 依次共用已保存的候选、核验和议题位置。生产选型依据各阶段的增益与误伤，不预设最终必须保留三个模型调用。校验失败沿用当前决策分支的失败语义，不能把未核验候选当成已确认的新结果。
