# 两场新会议测试：语义复核与可接受答案

IS1000a 和 TS3003b 已用当前 v19 配置跑完。主助手先通读全部原文、重注并冻结可接受答案，随后亲自核对全部最终任务、决策、确认卡和相关后续发言。按有依据的内容匹配，两场 **7条任务内容均可接受、7项任务参考全部覆盖；23个决策主张均可接受，决策栏目命中18/20项参考**。两处决策栏目漏项在事实栏保留。

这些分数不能解释成每条记录都能直接用于分派：IS1000a 有一条任务把两份设计职责合给同一人，负责人不可靠；TS3003b 的未决栏重复列项，并将部分已选方向重新写为未决定。下面将内容匹配、负责人约束和栏目状态分别报告。

## 测试与判分条件

两场来自此前未用于本地调优的两个参会小组：IS1000a 是约25分钟的启动会，389段；TS3003b 是约37分钟的功能设计会，404段。全量原词覆盖均为100%。选样只依据会议组、参考数量、时长和既往使用记录，在推理前完成；两场仍属于 AMI 遥控器设计场景，结果支持扩展到新参会小组，不足以代表跨领域泛化。[测试计划](两场新会议_v19_测试计划.md)

保持 context-v5 v19、决策核验 v2、DeepSeek flash 及原推理配置，两场分别用空历史、新 SQLite、新响应目录，从正常 Service 入口完整运行。没有因成绩修改生产代码、提示或重跑。重注参考没有进入模型输入。

原 AMI 标注保留，另建含证据、可接受答案和不可接受扩写的参考：IS1000a 为3项任务、8项决策；TS3003b 为4项任务、12项决策。主要调整如下：

- IS1000a：将同一句中的利润目标与国际市场拆开；原标注把基础功能写成必要按钮清单，而第359段明确将具体按钮留待下次，所以重注为基础功能方向；补充明确的设计目标和项目阶段。
- TS3003b：补入主持人归档纪要、营销人员继续调查老年市场的承诺；趋势观察允许与界面概念合并或分开，负责人含混时可待确认；补入后来明确认可的常规材料决定。
- 所有运行前参考保持不变。运行后只补充了**内容匹配与负责人完整性分开报告**的评分说明，因为第一场出现有内容依据但绑定不可靠的合并任务。冻结的含负责人约束结果同时保留，未将其静默改成全对。[口径说明](../runs/2026-11-18-two-unseen-v19/scoring-clarification.json)

## 可接受答案怎样落到具体判断

**TS3003b 的个人调查承诺应算任务。** 前文说“也许应该研究老年人需要什么”，如果只看这句，可以认为是建议；后文 D 又说自己需要进一步了解该方向。最终 R13 合并成继续调研，保留同一个人的承接，不扩写额外交付物，判正确。R3 归档纪要也有主持人的明确承诺，两项均在推理前补入参考。

**趋势观察单列、负责人待确认可以接受。** R15 保留用户界面概念，R16 单列趋势观察。原句没有清楚点名趋势观察由谁承担，输出没有编造人名，而是给出确认卡。它与原标注合成一项工作的粒度不同，不因此计误提。

**选定方向后仍需成本或市场调查，可以共存。** 最终已保留 teletext，也已聚焦老年人，后续成本约束、市场验证不必推翻这些方向。第二场的普通小LCD经过讨论取代昂贵触屏，主持人在总结中同时列出底座与LCD；本次认可这些设计方向，不机械要求每个子句再出现一次“正式决定”。

**底座包含充电属于可接受但有边界的解释。** 最初提出的底座方案包含寻物和充电，后文认可整体底座且未排除充电。主分接受这一整体采纳。如果另采用“子功能必须再次逐项重申”的规则，只将充电这一主张列为争议，第二场决策精确率为12/13，而不是整条底座、寻物都算错。该敏感性不改变参考召回。

## 仍需处理的三个具体问题

### 1. 第一场工作内容没丢，但不能放心直接按当前负责人分派

IS1000a 的 R16 将“一般设计”和“技术功能设计”合为一条，并全部绑定 C。第370–377段连续使用 `you`，C 紧接着回答同意，因此绑定并非毫无依据；但是角色信息和原 AMI 参考分别指向 UI 一般设计、ID 技术设计，文本不能可靠证明这两份工作都改由 C 承担。

溯源中，解释阶段已经完成合并并绑定 C；核验继续以邻接的同意回应认可该绑定，没有把两份职责分别核对。较稳妥的输出应拆开职责，或明确负责人仍待确认。R15 的需求研究则保留“被点到的两人”，作为候选请求确认；它也没有恢复原参考中的营销人员绑定，但没有假装人员已经确定。

为避免内容高分掩盖分派风险，按冻结的含负责人约束、整条记录口径另算：

| 会议 | 可接受的完整任务记录 | 完整记录参考命中 |
| --- | ---: | ---: |
| IS1000a | 1/2，50% | 1/3，33.3% |
| TS3003b | 5/5，100% | 4/4，100% |
| 合计 | 6/7，85.7% | 5/7，71.4% |

这里把第一场 R16 整条视为不通过，所以它的两项内容命中不进入这一严格分数；不表示两个工作都从输出中消失。候选中明确写出的待确认可以通过“忠实保留不确定性”的要求，也不等于负责人已获确认。

### 2. 决策栏目遗漏两项，整份纪要仍保留

| 会议与参考 | 路径 | 最终所在位置 |
| --- | --- | --- |
| IS1000a D4：国际市场 | 草稿决策为空；独立扫描发现“目标市场区域”，最终裁决未保留 | 事实第7条：欧洲、北美，可能包括亚洲 |
| TS3003b D11：语言市场适配 | 草稿已有；独立核验因具体实现未定标为open；裁决删除 | 事实第15条：按不同语言/文化市场分别投放 |

因此决策栏目召回为18/20，跨事实与决策栏目看，重注参考的内容覆盖为20/20。前者反映结构化输出是否完整，后者反映用户在整份纪要中是否还能找到内容。不能把两种口径混用。

### 3. 第二场未决栏与决定栏状态不一致，并重复列项

TS3003b 最终有10条未决记录，其中有4组重复：第1/7条是数字键，第2/9条是底座与LCD，第3/8条围绕LCD预算，第6/10条围绕老年市场验证。后加入的表述还把“预算或市场待核实”扩写为“是否加入屏幕／是否定位老年人仍未决定”。早期触屏可行性问题也保留为当前未决，未充分反映后文转向普通小屏。

这不是所有未决都应删除：老年用户的具体额外需求、市场判断、成本核实仍有依据。问题是未决对象需要写准，区分“方向已选，执行参数待核实”和“方向尚未采纳”。

阶段记录可以定位重复的来源：纪要核验保留原 U1–U6，又将事实候选 F13、F16、F17、F18 改写为未决项；修正复检通过后，[合并逻辑](../meeting_eval/minutes_review.py)直接追加，没有消除它们与已有未决项的语义重复，也没有与最终决定统一状态。主助手已逐条记录全部10项的判定，未把这一栏的错误藏在任务、决策精确率之外。[第二场逐条复核](../runs/2026-11-18-two-unseen-v19/TS3003b/人工逐条复核.md)
