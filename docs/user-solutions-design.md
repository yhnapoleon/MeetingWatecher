# 五项问题的方案与验证口径

2026-11-16。以用户对 M2、待定事项和 C23 的判断为产品契约。可选策略 context-v5；默认仍为 split-v3。新增模型阶段为零，继续采用一次解释、一次核验、必要时一次修正与再核验。

## 1. 明确工作不重复追问

M2 的范围调整已明确动作、对象和今天，缺的是个人归属。历史输出的问题来自两个位置：reduce_context 把已经被 gap_checks 关闭的 owner 错误重新加入 missing_fields；又把没有个人承接当成未作执行决定。

v2 及以后只从已核验的 gap_checks 生成信息缺口，check.issues 继续表示解释错误。commitment 新增 decided，表示已决定执行而未指定个人，必须有原话证据；不会赋予个人承接或自动创建权限。decided 工作保留为候选，只问实际缺少的负责人。assigned、suggested、conditional 分别保留个人待承接、建议待采纳和条件尚未满足的含义。缺省问题按缺口字段组合。

验证：保存的真实失败响应回放；decided 无负责人仍产候选并保留今天；完整 M2 入口验证旧任务完成和新范围工作并存；显式配置/测试正例只产生一项落实工作。

## 2. 新增记录的身份由程序绑定

introduced_by 在旧协议 properties 中但不在 required，生成示例省略，末端消费者却直接读取。JSON Schema 的属性声明本身不要求属性存在；这是契约不一致，不能简单归因为后处理丢字段。[JSON Schema 对象规范说明](https://json-schema.org/understanding-json-schema/reference/object)

复用 v4 的 repair_contract/expand_patch：程序提供目标槽位和 finding 槽位，模型只填写语义内容；程序生成 record_id、thread_ids、introduced_by。检查范围摘要防止使用过期响应，拒绝未知槽位或模型填写身份字段。无须把 introduced_by 强制加到所有正常记录。

验证：将历史缺字段的真实响应内容映射到新槽位，确认身份自动补齐而描述不变；未知 finding、过期 scope 必须拒绝；真实模型遗漏补回案例核验后合并。

## 3. 待定事项只收集

增加 deferred_topic，仅用于明确暂缓的议题。它携带描述、证据及暂缓含义，不能带执行事件、缺口或问题。归约结果进入 deferred_topics，纪要单列“待定事项（仅收集）”。context-v5 的 facts 分支不再重复收集同类暂缓议题；不按相同证据段粗暴去重，以免丢掉同段不同问题。

没有截止日但明确要做的工作仍为 work。同一会议后文明确推进时更新为 work；跨会议自动追踪/激活待定事项不在当前原型中。

验证：M1 暂缓监控面板进入收集区，不再产生追问、执行任务或重复的未决问题条目；事实摘要可以复述原话。无日期任务保留；后文明确推进变为工作。分类错误仍可能造成分支遗漏或重复，因此还须检查正常 Service 输出。

## 4. 核验对象固定，新增建议另走修正

两次 Incomplete event checks 都是返回了多余 E2，不是漏 E1。旧 schema 允许任意 event_id，模型把发现新工作与核验输入事件混在一起；末端集合检查使整次核验失败。

新核验响应使用 record_id 为记录键、event_id.field 为事件字段键，例如 E1.work、E1.time，每个键对应一个必填槽位。程序校验完整且没有额外键后再展开为内部列表。分类变化和遗漏发现保留专用字段，不允许核验直接创建事件；修正阶段负责产生事件。检查与再核验均绑定范围。旧列表协议的错误信息分别报告缺失、多余、重复 ID。模型仍可能违反协议，此时明确失败，不静默删除多余内容，也不声称能保证所有请求成功。

首个原型曾将每个事件嵌套在 E1 对象内，实测出现 JSON 括号错误；最终设计展平事件字段，减少一层嵌套。继承提示中要求填写 candidate_guids 的句子也改为只核验输入字段，避免把解释阶段字段混入核验输出。发送给模型的 schema 明确 additionalProperties=false，与本地严格校验保持一致。

验证：原 E1/E2 失败响应中 E2 被准确拒绝；保留发现字段的正确 E1 响应可通过边界；真实模型检查遗漏场景，同时验证原有 E1 更新仍保留。

## 5. C23 改为检验明确内容

必须保留会后联系袁校长并继续沟通其他问题；推断“补问未听清内容”不是必写项。原文明确补问仍须保留；无关信号背景不能变成新的补问义务。旧 12 份输出按新口径通过属于评分规则变化，不是模型提升。

验证：原文、明确补问正例、信号已解决且联系报名问题反例；不把关键词检查作为最终语义结论，逐项对照原话复核实际描述、归属、时间和操作。

## 调研依据与适用范围

会议任务研究将识别相关对话和抽取任务描述分开，讨论提议、承诺及任务内容的不同作用；这里采用这种区分来分析根因，不直接照搬文献的标签或成绩。[Purver 等，SIGDIAL 2007](https://aclanthology.org/2007.sigdial-1.4/)

验证分为确定性契约测试、固定上游的协议试验、完整 Service 正常入口。记录首次失败，不自动重试；旧实验数据不改。小样本验证说明这些例子的表现，不等于全量语料通过率。结果另见本目录的 user-solutions-results.md。
