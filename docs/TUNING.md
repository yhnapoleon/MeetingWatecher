# 任务与决策提取调优记录

## 1. 从一句会议发言看误提取

ES2002b 中的 “I'll add it later, I guess the presentation.” 表示稍后在会议展示中补充说明，旧输出却把它当成未来制作工作。只看 add、later 和 presentation，容易补出并不存在的交付物；需要读前后发言，判断这句话是在安排工作，还是在组织当下的讨论。

context-v5 v19 增加 meeting_discourse 与 unclear_intent 的区分。前者不产生工作，后者保留为待澄清意向，由用户补全内容和负责人后通过 clarify_and_add_task 创建任务。本轮完整重测中，该句最终为 context_only / meeting_discourse，没有任务或澄清卡。

本文按问题机制组织调优，覆盖任务边界、状态归并、证据协议、决定裁决和跨会承接。每项区分真实新推理、固定输出回放、失败阶段恢复与事后重新计分；原始预测和冻结标签继续保留。

## 4. GN25：覆盖检查读到了条件承诺，仍未保留工作

原文 qm.Bed011.639 表示：如果大家认为 Grad B 参加 Santa Barbara 会议合适，团队就支付费用。解释将其与参会和访客安排合为 context_only，核验以“尚未形成决定或分派”为由认可。

改动在 coverage_review 加入 nonwork_record_evidence，让核验继续检查背景、暂缓和已解决记录中的独立工作；即便一句话已经被别的工作引用，也检查是否还有另一个动作。其后固定解释结果，仅比较核验设置。

## 5. v17：输入证据对象与输出 ID 混用

ES2002a 完整会议第一次以 v16 运行时，全文四个跟踪窗口通过，工作解释两次却返回证据对象数组，接口只接受证据 ID 字符串数组。两份草稿均已含三项参考分工，但因协议不通过，最终任务项和确认卡为零，状态为 partial。

离线探针只把证据对象改成 ID 即可通过解释结构校验，说明故障发生在协议边界；它不能直接作为有效结果，原草稿还存在越界和单字符引用。溯源发现提示混用了输入 span 与输出 ID、解释缺少 output_schema、证据补丁被完整 schema 门槛挡住、错误反馈丢失具体类型。

v17 将输入说明和输出契约拆开，解释使用封闭 schema；完整草稿的引用类型错误允许一次非思考 strict 补丁，错误反馈结构化。恢复前核对完整输入、历史、tracking 配置和代码摘要，复用已验证跟踪及事实/决定，重新执行工作分支及依赖它的纪要核验。

## 7. 跨会：先检查历史里是否有任务

完整 b/c 顺序运行中，首场三位成员的分工保存为候选，承接尚未确认，没有成为次场历史任务。次场恢复后识别出三段研究汇报，但 target_guid 为空。这个现象不能直接归因为模型不会关联：用于关联的对象还未进入历史。

定位对照通过正常 resolve_requirement(add_task) 模拟确认三项候选，再以次场 71 段真实汇报输入运行。三项均关联原任务，新增任务为零；David、Craig 仍为 open，Andrew 被更新 done，后者需要复核完成依据。

完整实验仍暴露两个独立问题：c 场“尽快整理本场纪要”误关联 b 场纪要；“下一阶段安排”跨不同阶段匹配，完成依据不足。后续应让任务描述、历史匹配和证据核验同时保留会议与交付物范围，而不是只按负责人及相似动作判断。

决定侧正确保存四项重申，但新供电方案“动能辅助＋电池后备”只进入事实，未更新有效决定。这是早期整会处理结果。当前增量应用把所选片段中的动能方案标为未采纳提议；两者输入范围与处理链不同，分别保留判断。

## 8. 整会提取阶段的结论

可归因的程序修复包括进度卡错误路由和证据契约；含糊语句、条件承诺、决定裁决和跨会完成状态仍需原文语义判断。评测中应同时检查识别内容、字段、卡片资格、实际任务状态及持久化，避免一个高分遮住另一个环节的错误。

下一轮先用现存原文、解释、核验和归并记录定位共同机制，再选择受影响的少量样例验证。GN25 的两轮负结果、GN33 回退、红外及供电漏项都已保留，不重复相同提示后继续试跑。具体输入、配置、参考、结果和可复算范围见[证据索引](EVALUATION.md)。

## 9. 会中生成：把一次完整总结拆成有证据边界的增量更新

第一版真实摘要按较大的转写范围一次返回，供电问题、反对理由和讨论倾向同时出现，读者看不到信息如何随会议形成。改变显示动画不能解决这个问题，因为模型已经读到了后续发言。

改动从输入边界开始：每轮约取 12 秒新增稳定转写，带上此前议题和少量前文；同一议题返回原 ID 的修改，新议题才新增卡片。每次更新保存证据、覆盖游标、版本和作业 ID。模型处理落后时逐窗口补齐，不把积压内容合成最终摘要。行动事项也由同轮 work_changes 产生，不依赖用户先发起文字提取。

正常速度片段从空列表开始，先出现供电问题，再补充反对理由和当前倾向；行动事项实录约第 33 秒出现首项、第 53 秒加入三人分工。多人同一句分工可在同轮出现，不人为错开。验证既检查可见卡片，也检查作业覆盖时间及证据 ID，详见[增量更新记录](会中纪要增量更新_实现与验证.md)。

## 10. 第二场：已有结果必须能完整阅读和对照

三人汇报进入后台后，旧多列布局仍可能将正文压到视口外，只露出卡片边缘；自动任务状态条出现时又会改变可用高度。修复把当前议题和目录分开，按实际可用高度布局正文，状态条由独立容器参与测量。任务页加入上场分工与本场进展对照，原话和确认直接对应同一任务。

数据层同时补齐 prior_topic_id、relation 和 category：上场卡片以历史对象提供给模型，只允许引用，不能作为本场卡片修改；新增要求、重申、质疑与提议分别保存。曾出现的 JSON 格式错误允许一次格式修复，修复后仍执行引用和对象校验。修改材料时，将用户本轮修改要求放在工具返回之后，避免长上下文让模型只复述旧表。
