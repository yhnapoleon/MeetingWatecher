# 行动项证据流程：实施与验证结果

2026-11-14。新增的 `evidence-v1` 已能从原有 CLI 导入会议，逐步保存工作证据、解释和核验结果，再由程序决定新建、更新或待核对。默认仍为 `split-v3`。六个难例上，新流程减少了虚构动作，但跨句分工仍有遗漏，尚未达到方案规定的默认切换条件。

最能说明变化的是这句话：“我们会把这个视频剪辑，然后给大家确认，然后还有这个文稿可以吧。”原直接抽取会生成“整理文稿并发送确认”，或把文稿混进视频任务。新流程三轮都只保留有明确承诺的视频剪辑；文稿没有确定处理动作，不能仅凭它和视频出现在同一句就当作另一项工作。

**实际改了什么**

原来的校验能检查引用是否存在，却不能确认引用是否支持整条任务；评分又主要依赖核心证据段，因此错误描述可能得到正确分数。本次先补了独立语义复核：分别判断工作内容有无依据、是否完整、负责人、承接、时间和操作是否正确。评分程序只计算复核结果，不使用抽取模型自己的核验意见作答案。复核绑定输入、标签和完整预测的哈希；预测变了必须重评。已有一轮 `split-v3` 的 21 例保存结果，锚点 F1 为 75.0%，按内容复核为 66.7%，完全正确任务 F1 为 58.3%；把全部描述换成采购服务器，新评分为 0。两套口径分别保留。

新策略按三个步骤处理原始逐字稿：找工作相关发言；解释工作、负责人、承接、时间、状态及旧任务关系；核对这些判断及明显遗漏。每一步都读原文并保存记录。引用位置由代码进行精确匹配；模型提供引文，程序计算字符位置。解释步骤可以补回定位步骤漏掉的工作，前一步候选不再限制后一步只能从中选择。

任务新建与旧任务更新共同使用这批事件。代码依据操作所需的证据作决定：新建需要可靠的工作内容、负责人和承接；完成旧任务需要可靠的完成事实、本人身份与唯一旧任务关系，不能要求完成汇报再次表达未来承诺。实际账号映射、读写权限、幂等写入和回执恢复仍由原有 Service 处理。失败记录为 `partial`，不会变成成功的空任务清单；恢复只重试失败步骤，成功的上游结果继续使用。

还有两处经独立审查复现后修复：被否定的截止时间可能仍藏在标题里，所以不能只清空日期字段后继续创建；子集评测的标签快照必须与复核使用的子集一致，否则正常评分入口会报哈希不匹配。未知时间可以留空；已经生成、又被核验否定的时间断言则阻止该项执行。

**如何比较**

使用 C02、C03、C09、C20、C21、C26 六个既有难例，每轮共六条参考行动项，来自五个会议系列，英文、中文各三个片段。每种配置独立运行三轮。它们是用于定位错误的开发材料，分数不能代表所有会议，也不能和完整 21 例的旧 F1 直接比较。

输入与语义标签在查看新输出前冻结。C03.2、C09.1 的短回应承接存在歧义，主标签仍保留原来的 `create`，同时单列不确定性。C09 要求保留“用户对说明书的看法/使用问题”；笼统写“看看说明书”只算提到了对象，不算内容完整。C19“会后”、C20“后面”在 v2 中不再被视为交付期限，旧标签不变。全部复核标为 `agent_reviewed`，尚无独立人工复核。

| C21：我们会整理意见 | 恢复后为 3/3；初版为 0/3 | 初版定位漏掉后，下游也直接放弃；允许解释步骤读全文补回后改善 |
| C26：可以细化场景 | 三轮都作为建议保留，不进入承诺任务 | 事件存在与任务可以执行分开判断有效 |

把 C02 和 C03 合成连续分工窗口后，另作三轮对照，窗口内三项分工全部计分。直接推理每轮都找到三项，但额外生成发邮件任务，并把开展时段填成截止期限；内容 F1 均值 85.7%，完全正确召回均值 22.2%。新流程每轮找到 2、3、2 项，内容 F1 均值 86.7%，完全正确召回均值 55.6%。UI 分工仍只成功 1/3：两轮解释步骤把连续分工中的省略表达当作纯话题，核验也同意了删除。更高的 F1 没有改变这项召回失败。该视图第一轮事实分支格式错误，整例为 `partial`；任务分支结果保留，失败也计入报告。

核验前的事件另行复核，不进入执行入口。初版三轮完整覆盖参考工作的数量为 3、2、2，调整版为 4、4、4；核验没有提高这些数量。调整版核验过滤了第二轮的一条发送邮件事件，但没有补回 UI 分工或 C09 的研究目的。这说明主要剩余问题发生在解释阶段，继续堆核验步骤无法恢复已经被删掉的意义。

还做了只改变核验推理模式的对照：冻结初版核验的提示、输入和 8,192 上限，重评 16 份保存请求；相同请求复用后实际调用 14 次。C09 三轮的工作对象都得到支持，其中两轮允许输出“看说明书”，但内容仍不完整；C21 三轮都补报“我们会整理出来”的遗漏原话，却不能直接生成任务。另有两份结果因截断或 JSON 错误失败。该实验支持“核验能力影响结果”，也说明更强核验不能代替前一步恢复工作含义。[核验对照原件](../runs/2026-11-14-evidence-check-ablation/summary.json)

最终代码的自动测试为 69 项。真实回放还暴露了“完成旧任务却要求再次承诺”的错误：修复前一轮只通过 11/12，另两轮 12/12。用该失败写出回归测试，再按操作区分必需证据后，重新使用独立目录运行三轮 M1/M2，三轮均为 12/12，首次处理全部成功。它们检查任务日期与负责人、重放和重启不重复创建、不同身份的会前回顾、完成原任务、决定替代及六个权限状态集合。另从 CLI 重放已处理的 M1，未增加模型调用。真实飞书连接器仍不在这次离线验收范围内。

最终两次策略修正没有更改六例与上下文实验中已经保存的任务提议：对 37 份成功的任务阶段记录重新执行最终 reducer，`items`、`updates` 全部一致；失败的两份阶段记录不冒充可重算结果。原始 52 次诊断请求与旧评分也另行审计。

**采用决定与后续方向**

本次交付语义评分、可配置推理、可追溯的三步实验策略，以及恢复和写入规则修复。由于 C03 完整上下文仍漏提、C09 内容仍不完整，未通过小规模机制验证；按实施方案，暂不扩大到完整 21 例三轮和新盲测。新盲测清单已建立，但材料未就绪，不能宣称泛化提升。默认保持 `split-v3`，直接推理继续保留为较简单的对照。

下一轮优先改变解释阶段的任务：先还原连续分工中省略的动作、工作对象和研究目的，再单独判断承接；不能在还原工作含义时因为缺少承诺动词把工作删除。核验需要独立检查被删除的工作跨度，而不是沿用解释步骤的删除理由。可在已经建立的记录和评分上比较“直接推理生成完整工作，再做字段核验”与现有定位流程；先要求 C03/C09 连续三轮保留完整内容，再评估新增复杂度与预算是否值得。相关论文和开源候选继续见[系统溯因报告](action-architecture-diagnosis.md)，目前没有证据支持更换框架本身就能解决这些错误。
