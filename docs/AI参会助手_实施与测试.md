## 1. 当前可以怎么用

进入“遥控器产品设计”项目，点击右下角“项目助手”。会议页可以问项目、选择最近两分钟/五分钟补课、委派比较表或验证清单。勾选“自动影响提醒”后，系统根据当前已播放的供电/组件等讨论线索触发分析；每场最多 8 次，每个窗口避免重复分析。提醒可忽略、转为验证清单，或加入操作者自己的待办。

项目准备页提供会前简报；归档页提供设计评审与项目同步模板。完成的材料可继续修改，新版本保留旧版本，并下载 Markdown、HTML、CSV 或 ZIP。已有交付包切换模板时复用同一事实快照，只调整阅读组织，不重新生成业务状态。

原主视图仍播放预设中文事件；新侧栏独立调用真实模型并显示依据。当前输入来自 small.en 实际 STT 的词轴回放，按播放游标逐步释放；历史完整会议与业务状态只在对应会议完整归档、且本地已导入历史库后开放。在线 ASR 端到端与真实飞书写入属于后续接入。

本轮绑定的项目为 `remote`，对应 AMI ES2002b→c。新建的其他项目没有资料绑定时会明确提示，不套用这一项目的会议证据。

## 2. 实际实现

| 路径 | 用途 |
| --- | --- |
| `meeting_copilot/api.py` | FastAPI 会话、运行、事件续读、下载、影响建议采纳 |
| `meeting_copilot/memory.py` | STT 稳定发言窗口、游标过滤、FTS5 检索、Service 历史读取、业务记录到原话映射 |
| `meeting_copilot/jobs.py` | LangGraph 三节点、SQLite checkpoint、后台执行、取消与启动恢复 |
| `meeting_copilot/model.py` | 真实模型工具调用、结构化回答、请求/响应与用量记录 |
| `meeting_copilot/search.py` | 博查搜索与网页读取；保存来源，正文不可读时标记为搜索摘要 |
| `meeting_copilot/artifacts.py` | 比较表、版本材料、两种交付模板、HTML/CSV/ZIP 导出 |
| `demo/src/copilot/` | AG-UI HttpAgent、任务历史、原话抽屉、材料与提醒交互 |

实际链路为：页面登记当前会话→冻结请求 scope→模型调用 `search_evidence`→本地读取允许的证据→模型生成有引用的回答→校验引用→保存材料。LangGraph 的检索、生成、保存节点分别 checkpoint；标准 AG-UI 运行、步骤、工具、文本和结果事件保存在事件表中。当前模型回答采用完整 JSON 返回，页面显示真实执行阶段，没有模拟逐 token 生成。

每个 worker 操作独立创建数据库连接。历史数据库使用 SQLite backup 复制，新增的“加入我的待办”通过已有 Service/Simulator 写入独立 `actions.sqlite`。它创建操作者自己的任务，不替 David 等参会者接受候选分工，也不写真实飞书。

公开搜索是可选项。当前适配器沿用 Agent2 的博查结果格式，每次研究任务最多一个搜索查询、读取前三个页面；网页限制 HTTP(S) 公网地址、重定向次数、响应体积与超时。模型只能将外部资料作为研究来源，不能把它当成会议发言。

## 3. 本地运行

在仓库根目录建立可选环境，避免改变原标准库核心的依赖：

```powershell
python -m venv .venv-copilot
.venv-copilot/Scripts/python.exe -m pip install -r meeting_copilot/requirements-lock.txt
# 根目录 .env 使用已有 .env.example 的三项模型配置。
.venv-copilot/Scripts/python.exe -m meeting_copilot --env .env
```

服务默认监听 `127.0.0.1:8766`。可选参数：

- `--history-db <已有实验的state.sqlite>`：首次启动时备份至新运行目录。省略时只使用已播放/归档的 STT 证据，不假装已有业务确认状态。
- `--search-key <博查凭据文件>`：启用公开资料搜索；内容不会发送给浏览器或保存到请求日志。
- `--data <新运行目录>`：默认 `runs/copilot-local`，保存任务、checkpoint、材料及脱离 HTTP headers 的模型日志。

另一个终端启动前端：

```powershell
cd demo
npm ci
npm run dev -- --host 127.0.0.1 --port 4187 --strictPort
```

打开 [本地工作台](http://127.0.0.1:4187)。Vite 已代理 `/api/copilot` 到 8766。原静态 Sites 构建继续保留；静态托管本身不包含 Python 服务。

本次实际使用 `tmp/agent-research/.venv`，模型读取已有工作区配置，历史导入源为 `runs/2026-11-18-ami-bc-continuity/state.sqlite`，原库保留不变。服务与前端已在本机启动。

| 用例 | 结果 | 实测 |
| --- | --- | ---: |
| 上场供电与分工问答 | 引用普通电池依据，区分两项项目经理任务与三项候选分工 | 7.78 秒 |
| 第二场会前简报 | 历史决定、未确认分工、待讨论问题；未引入第二场未来内容 | 12.00 秒 |
| 最近两分钟补课 | 返回指定窗口的讨论，未把外观/按键建议变成已确认决定 | 8.53 秒 |

## 5. 暴露的问题与修复

1. **工具调用数与客户端假设不一致。** 第一次模型按问题拆成两次检索，比较任务又曾按维度拆成四次。现在查询规划明确要求合并关键词，执行端支持最多两次合法检索；超出预算报错并保留请求，不悄悄丢弃工具调用。
2. **业务记录与原话索引脱节。** 模型能看到归档决定和任务中的引用，但原话列表没有全部返回。已从 Service 记录补齐对应发言，并把决定/任务编号解析到实际原话。
3. **长引用编号抄写错误。** 简报曾把 STT 编号范围拼成不存在的 ID。模型上下文改用 E1/E2 短引用，保存结果时映射回原始 ID；校验仍拒绝不存在的引用。
4. **不同供电方案的风险混用。** 第一份比较把充电底座的影响延伸到了动能方案。提示改为逐条核对陈述所属方案，并重跑包含外部资料的比较；最终稿将已知机制、推测与待验证项分开。
5. **失败的提醒请求阻挡重试。** 原窗口去重也包含失败任务，导致第二次被拦截。窗口去重现在只针对未失败的分析；失败仍计入总调用预算。建议以受影响历史对象生成稳定键，避免仅因措辞变化创建重复提醒。

失败原件保留在 `runs/copilot-local/logs`、`runs/copilot-checks-v1` 及最初两次检查记录；最终结果另存 v2/v3/v4，没有覆盖失败文件。
