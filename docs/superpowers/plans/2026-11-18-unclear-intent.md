# 模糊意向分类与澄清实施计划

目标是保留模糊发言的已知含义，阻止把口头补充扩写成材料制作任务，并保留明确工作、条件承诺与正常省略分工。需求与调研依据来自本次对话及 [决策与行动分流验证](../../决策与行动分流验证.md)。

使用 Python 标准库与现有 context-v5 解释、核验、有界修补、Service 确认机制。模式识别由模型结合问答与后文证据完成，程序依据结构化分类限制任务入口。

- [x] 核验协议增加 meeting_discourse 和 unclear_intent 两种 work_basis。前者要求 context_only，后者要求 ambiguous 且有具体澄清问题。解释与核验共享对话模式要求，检查回复对象、动作对象、会中场景与后续澄清。
- [x] ambiguous 记录中经核验仍缺动作或指代的内容显示为 unclear_intent，保留证据和具体问题，can_add_task=false。工作内容明确但只有负责人、承接或时间缺口继续保留原入口。无新增语义核验依据的旧记录沿用保存结果。
- [x] 新增 clarify_and_add_task，要求有权限用户提供最终动作描述与映射负责人。沿用来源版本、权限、审计、幂等及重开恢复检查。已有任务关系未确定时不能借此新建。纪要单列待澄清意向。
- [x] 定向离线测试验证协议冲突、归并、正式确认、权限与恢复。56/56 通过；扩大至 116 项后为 115/116，剩余为已记录的旧版错误文本断言。
- [x] 真实实验包含原 R21 所在 87 段、会中口头补充、真正模糊意向、明确文稿修改、缺期限工作、跨句恢复对象和条件承诺。冻结输入与预期后经正常 Service 的任务分支运行，重新执行跟踪、解释、核验，使用独立数据库。另补无显式歧义提示的省略表述和后文澄清对照；R21 加跑与旧实验相同的关闭思考核验配置。
- [x] 保存报告、更新交接，记录误报、召回、澄清卡数量和模型请求。独立复核修改。

验收关注真实承诺被误归模糊、歧义被补造成任务、被降类后仍有建任务许可、未知历史关系被绕过、确认失败后重复建任务。实验只证明本次样例，不替代两场完整会议的新指标。
