# 飞书接口怎样改变样例和验收答案

核查日期 2026-11-13。核查依据为飞书官方服务端 Markdown 文档和本地 lark-cli 1.0.93 的帮助与 schema。以下请求、返回类型和错误码来自文档；真实租户的导出样式、任务可见性和写入结果需用测试资源回读。

## 妙记导出：适配器该模拟什么

官方接口为 `GET /open-apis/minutes/v1/minutes/:minute_token/transcript`。查询参数分别为 `need_speaker`、`need_timestamp`、`file_format`。最后一项可选 txt 或 srt；成功响应为文件二进制流。用户身份和租户身份均可请求，新应用使用 `minutes:minutes.transcript:export` 权限。接口列出的资源级拒绝错误为 403 / 2091005；转写尚未完成为 400 / 2091003。两种失败在统计中应分别归到访问与时机，不能当成一场没有待办的会议。[导出妙记文字记录](https://open.feishu.cn/document/minutes-v1/minute-transcript/get.md)

**第一个真实样本的采集单。** 用同一份获准导出的短会，指定带说话人与时间戳，分别保存 TXT 和 SRT；再保存一份关闭说话人选项的文件作为缺字段对照。登记请求选项、身份类型、会议日期来源、脱敏说话人映射和文件摘要。解析测试比对发言顺序、时间单位、原话及匿名标签的保存情况。接口文档没有承诺返回应用内用户 ID，也没有给出每种导出组合的逐字节模板；输入格式在拿到样本前保留来源标识。内部段 JSON 是评测器的统一表示。

妙记还可以生成智能纪要与待办；本机 CLI 用 `minutes +detail --transcript` 获取逐字稿文件，用单独的 `--todo` 取既有待办。比较模型抽取效果时对同场原生待办另存预测；只有确认生产模块本来就能读它，才把它列入相应条件的输入。[飞书智能会议纪要](https://www.feishu.cn/product/ai-meeting-summary) · [妙记官方说明](https://www.feishu.cn/hc/zh-CN/articles/022111234449-%E6%9F%A5%E7%9C%8B%E5%A6%99%E8%AE%B0)

## 飞书任务：必须补上的三个边界

| 平台契约 | 对产品和评分的影响 |
| --- | --- |
| **成功后幂等保留 5 分钟，不同调用者相互隔离。** 创建使用 client_token；成功但客户端丢回执也属于实际成功。超过时限，同 token 可成为新请求。[任务概述](https://open.feishu.cn/document/task-v2/overview.md) · [创建任务](https://open.feishu.cn/document/task-v2/task/create.md) | 把同一意图重放分成三例：立即、隔天、换身份。保存本地意图 ID、执行身份、首次发送时间与平台 GUID。跨窗口先用既有绑定或可唯一核对的业务标识对账。只有标题相同且没有 GUID 时，自动新建可能导致双写。 |
| **更新用字段掩码；完成操作作用于整条任务。** 出现在 update_fields 中但未赋值的字段会被清空；恢复未完成用 completed_at 的字符串值 0。会签/或签任务的 OpenAPI 完成不能表示个人单独完成。[更新任务](https://open.feishu.cn/document/task-v2/task/patch.md) | 改期只更新 due；指定“清除期限”才允许置空。单负责人明确自报完成可按试行策略更新。会签中一人发言只记其个人进展，不据此关整项。验证应读回任务并核对其他字段。 |
| **任务成员、所在清单和来源文档有各自的授权关系。** 负责人可读写，关注人可读，创建人默认有编辑权。分享至群、协作文档和清单可能增加有效读者。用 tenant token 的应用也受资源范围限制。[任务鉴权](https://open.feishu.cn/document/task-v2/task/overview.md) · [任务 FAQ](https://open.feishu.cn/document/task-v2/faq.md) | 内部源会议、共享任务、来源引文分别判权。共享任务标题若含私密会议内容，在创建前就检查目的清单的受众；生成回顾时再按每个查看人的实际可见字段筛选。 |

## 从平台事实到验收记录

| 测试操作 | 应保存的证据 | 怎样判断 |
| --- | --- | --- |
| 同场比较 TXT、SRT、可选字段缺失 | 原件哈希、导出参数、解析后的发言顺序与时间 | 首末段、换人点、缺失值逐一核对；保留平台未支持或未实测的组合。 |
| 单次创建、重复读取、再改期 | 同一业务意图、GUID、原/新期限、其他字段的读回值 | 同一承诺最终只有一个对象；改期不会清空负责人或标题。 |
| 会间完结，再重新打开 | 每次读回时间与 completed_at、会前快照 | 准确反映会前状态；让过期本地提示仍显示已完成可检出错误实现。 |
| 两人对同一任务查询；外协尝试访问原妙记 | 两人各自可见的任务字段、来源读取响应、回顾正文与引用 | 应见任务完整，受限原话及其标题不会进入外协回顾。只读用户的更新尝试也要能与成功写入区分。 |

执行首轮离线评测时，用模拟器表示这四种平台情况。取得测试空间和脱敏真实导出后，沿同一组检查项做实际回读。集成记录只需测试标识与状态变化，账号凭据不属于评测样本。
