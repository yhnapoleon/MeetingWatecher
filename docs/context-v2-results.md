# context-v2 实施与检验结果

2026-11-15。**修复方案已实现为可选策略 `context-v2`。原始跨会 M2 和明确落实正例各两轮首次通过，但扩大回归未全部通过，因此没有替换默认策略。** 新实现可以实际补回遗漏工作、核验后关闭误报遗漏，并将系统解释争议与用户待决定事项分开呈现。

## 1. 用户可观察的变化

原始 M2 的范围句“登录改版第一批的范围今天改一下，内部员工和试点客户都开放”现在作为决定背景保留。在两次完整 M1→M2 回放中，系统都完成同一 GUID 的案例整理任务，保留原 due_date/due_text，用新范围替代旧决定，没有新增范围任务、负责人确认或遗漏残留。

在原文后追加“陈可今天下班前改好灰度配置并发测试”—“好，我来”，两次完整回放都创建了唯一落实任务：负责人陈可，期限为 2026-11-16，旧任务仍正常完成。决定与工作共享证据时，实施工作没有被删除。四次回放均检查了权限隔离、历史查询、重复处理及重启后的任务/决定/intent/审计记录不增长。

当只有遗漏、现有记录都已通过核验时，新流水线也会进入一次修正；有效新增拥有独立记录和事件身份。误报遗漏只有在处置与对应关系被再核验后才关闭。修正失败时保留已有有效工作，未解决的遗漏以一条记录显示，不再同时出现泛化任务确认和重复遗漏确认。

## 2. 实现位置与规则

| 实现 | 行为 |
| --- | --- |
| `context_protocol.py` | 独立版本结构定义生成完整 JSON 示例；先检查必填结构再定位引文；检查 gap/clarification 的一致性 |
| `context_coverage.py` | 固定首次 finding 身份、修正目标与新增命名空间；验证处置对应关系；保护未选记录及退化前的受支持记录 |
| `context_v2.py` | 跟踪→解释→核验→最多一次修正/再核验；保留旧事件 ID，新增事件从全局最大 ID 后分配；最终候选引用可追溯 |
| `context_v2.reduce_v2` | 复用既有创建/更新规则；局部负责人错误保留真实候选，动作含义失败转为系统解释未解决；保留真实内容消歧问题 |
| `extract.py`、`service.py`、CLI | 接入 `context-v2`，沿用授权、SQLite、幂等及人工处理接口；纪要区分解释未解决与用户确认 |

首次核验只要求 coverage_findings，再核验只要求 disposition_checks；不向模型同时要求旧 uncovered_spans。旧事件校验器所需的空列表仅在程序内部适配。proposed_kind 仍是修正建议，不能直接应用为最终分类。

源码没有新增依赖，仍使用 Python 标准库。旧 `context-v1` 保留，默认仍为 `split-v3`；新策略和配置需要新数据库，已有已处理会议不会被静默迁移。

## 3. 定向检验与程序回归

七个定向样例覆盖：原始 M2、落实正例、C20 附带文稿、P07b 普通对象省略、两个未选定对象、明确文稿发送、同段第二项工作。它们均经过真实跟踪、解释、核验及必要修正。

| 检验 | 结果 |
| --- | --- |
| 初版定向检验 | 第一轮 7/7；第二轮 C20 失败，保留首次记录 |
| 修订后定向检验 | 两轮各 7/7，共 14/14；真实对象竞争仍阻断，明确文稿发送和同段工作保留 |
| 完整原始 M1→M2 | 两轮首次通过，零额外任务/错误确认/finding |
| 完整落实正例 | 两轮首次通过，唯一落实任务及原任务更新均正确 |
| 程序回归 | 171/171，其中本轮新增 37 项 |
| 最终代码离线重放 | 14 份定向请求/响应逐阶段重放，可观察输出全部一致，0 次网络调用 |

初版 C20 的核验错误继承了视频动作，又将文稿列为遗漏；再核验还漏了处置字段。修订明确了附和不能补出原话未建立的动作，并让生成的再核验示例展开处置元素结构。独立审查另外复现并修正了两项程序问题：负责人字段错误不应丢掉已明确工作；event.work 被否定时不能仍向用户泛问“这项工作”的负责人。相关测试均保留先失败、后通过日志。

落实正例的评估脚本最初漏保存 m2-input.json，导致评估中断，但会议处理已完成。核对 SQLite 中实际源文本后补齐该评估产物并离线重跑评分，没有重新调用模型；这不是模型结构恢复。

## 4. 扩大回归结果及未通过项

扩大回归包括 30 段真实语料、33 个边界/承接对照、10 个上下文/取消场景、一个连续分工场景和 13 个旧任务更新契约。首次结果与一次恢复分别保存。

| 范围 | 结果与口径 |
| --- | --- |
| 33 个对照 | 33/33 首次可观察契约通过，未出现 interpretation_unresolved |
| 30 段真实语料 | 29 段 processed、C19 partial；输出 17 项，审计口径 16 项完全正确；精确率 94.1%，召回率 88.9%，整例 28/30 |
| 旧任务更新 | 首次按当前 M2 预期 3/13；连接恢复后 12/13，HT04 仍未通过 |
| 上下文/取消 | CP07 一次网络恢复后，10 例的 23 条原冻结标准通过；另发现 CP01 的额外解释未解决残留，不能据此称全部新增语义要求通过 |
| 连续分工 | 三项工作及负责人、承接分别正确，UI 未接受的工作仍为候选 |
| 54 例综合批次状态 | 首次 42 processed / 12 partial；一次恢复后 52 processed / 2 partial |

首次综合批次后半段有 11 例遇到 TLS 握手超时或 EOF，共 27 次请求未收到响应。确认端点重新可达后，在副本上对 12 个 partial 各恢复一次，新增 48 次请求。恢复解决了网络中断，但 C19 和 HT04 暴露出下列协议问题；没有把恢复结果合写成首次通过。

具体残留：

1. **C19：引用与核验契约。** 首次解释的重复短引文缺 occurrence，仍被严格证据校验拒绝；一次恢复通过了引用定位，却在核验中撤回原问句而没有对应 question issue，再次被一致性检查拒绝。该例仍未生成可用任务。引用 ID 方案尚未实施。
2. **HT04：真实关联歧义的字段矛盾。** 两条旧任务的摘要、负责人和期限相同，确需用户选择。核验给出 needed/relation 问题，却将 relation gap 标成 blocking_for=none，结构契约拒绝该矛盾结果。原任务没有被误更新，但应呈现的具体关联问题未成功产出。
3. **C23：行动项遗漏具体目的。** 新 item 为“会后单独联系袁校长，就其他几个问题继续沟通”，没有保留核对刚才未听清内容的目的；信号背景仅在 trace 描述中。按冻结的 item 评分对象，content_complete=false。独立复核同意这一判定。此前 context-v1 首次审计口径为 17/18 完全正确，本轮为 16/18；这是实质退化，不能用 M2 改善抵消。
4. **CP01：背景仍留下解释残留。** 主任务范围和小林承接已正确，设置页名称未统一的背景却先被提为潜在需求，修正后仍未可靠关闭。最终没有虚构新任务，但多了一条 interpretation_unresolved，扩展验收仍算失败。

两套原始/审计语料评分都保留，未修改旧标签。旧任务 fixture 中 M2 的“pending=true”与当前“范围决定不应生成待确认工作”冲突，因此单独给出旧口径和当前口径：当前只移除该过时期望，并增加零额外 items/reviews；其他契约未放宽。

**扩大回归的无新增退化门槛未满足。** 当前版本适合继续在显式 `context-v2` 下验证，不能宣布全量修复或替换默认策略。下一步应处理核验结果的冗余字段矛盾、record/event 两份工作描述的内容漂移，以及背景记录的修正失败；不能清空缺口、直接采用 proposed_kind 或隐藏 unresolved 来提高通过率。

## 5. 复现、交付与成本

在项目根目录用新输出目录运行：

```powershell
python scripts/replay_mvp.py --out runs/my-context-v2 --strategy context-v2 --inference-config experiments/action-context/compact-check.json
python -m unittest discover -s tests -v
```

七例检验、落实正例、完整回归及一次恢复入口是 [run_context_v2.py](../experiments/task-boundary/run_context_v2.py)。最终离线重放入口是 [replay_context_v2.py](../experiments/task-boundary/replay_context_v2.py)，评分入口是 [score_context_v2.py](../experiments/task-boundary/score_context_v2.py)。运行名不可覆盖已有目录。

全部产物在 [runs/2026-11-15-context-v2](../runs/2026-11-15-context-v2/)：源码快照、输入、模型请求/响应、SQLite、纪要、操作日志、首次/恢复结果、独立审查及测试日志。主结果见 [summary.json](../runs/2026-11-15-context-v2/summary.json)。

本轮合计 **606 次请求尝试，579 次收到响应，27 次传输失败；响应记录合计 2,400,037 tokens**。其中一次恢复新增 48 次请求、181,926 tokens。计数不包含上轮研究实验，也不把恢复目录复制的旧请求重复计算。所有真实写入均在本地模拟器，未进行真实飞书平台写入。
