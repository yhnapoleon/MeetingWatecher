# 字段缺口不再使明确工作退出任务清单

2026-11-15。原失败是“我来整理合同，下次会前完成”：模型已经识别工作、负责人和相对期限，却因为不知道下次会议的日历日期，要求补日期并阻断任务输出。当前 context-v1 会保留这项任务及“下次会前”，具体日期为空。默认 split-v3 不变，任务写入仍是本地模拟器。

## 方案与实际改动

[调研设计](field-preservation-design.md)将工作内容、承接和时间分别处理，[实施计划](superpowers/plans/2026-11-15-field-preservation.md)记录了失败测试与检验步骤。设计借鉴会议子对话分析、TimeML 时间关系、逐字段状态操作及按必要性澄清；研究依据支持设计方向，不代替本项目验证。

新增 context 专用新工作处理器，旧 evidence reducer 不变：

- 已支持的相对期限无需先换算日历日期，保留原文和 null 日期；消除这种原因产生的多余时间问题。
- 工作明确但承接核验不足或矛盾时，保留候选与确认问题，不自动创建；不修改模型原始判断来伪装成“已承接”。
- 期限尚未选定时，保留候选但不写入有疑问的日期。若模型连工作描述中的时间都判为错误，仍保留可见确认记录，不将可疑标题展示为已核实任务。
- 内容、指代、范围、任务关系存疑，以及隐式目标、仅建议等情况继续限制执行。已有任务改期/取消期限规则和权限检查不变。

提示区分新任务的相对期限与旧任务具体日期更新，并要求结合回应者、回应对象、当时范围判断承接。研究目的需要推断时，应保留完整假设并针对范围提问。

独立代码审查发现两个组合问题：记录级承接/时间疑点仍可能在新处理器之前阻断候选；承接和时间同时有疑问时，相对期限会丢失或留下过时日期问题。两个问题均先写失败测试，再做局部修复。119项程序测试通过。两项旧测试原本要求时间缺口产生空任务列表，按用户新契约改为候选且不写日期。

## 实验与结果

八个中文正反例在模型调用前冻结，涵盖相对日期、无期限、他人回应、建议、明确自愿承担、两个期限未定、隐式目的与纯通知。旧代码独立跑基线；修复版复用跟踪、事实和决策输出，只重新解释和核验，正常 Service 入口与新数据库运行。八例是合成机制检查，不是盲测。

| 检查 | 结果 | 能说明什么 |
| --- | --- | --- |
| 中文八例机械契约 | 旧版6/8 → 修复版8/8，均首次 | 任务/候选数量、日期字段、必要确认类型符合冻结预期 |
| 旧十三例更新重放 | 13/13 | 最终代码复用保存的语义输出，经Service确认旧状态/日期更新不回退 |
| 最终全新 M1/M2 回放 | 首次12/12 | 正常生命周期、权限、幂等、跨会更新通过 |
| 程序测试 | 119/119 | 字段组合、权限与存储行为通过 |
| 旧 evidence 输出复算 | 37份一致 | 旧策略 items/updates 保持 |

八例机械通过不等于全部语义正确。逐条复查发现 FP02 将“工作目前没有约定截止时间”写成“该合同付款条款没有约定截止时间”，日期字段虽正确，描述的修饰对象有偏差。FP07 能保留隐式目标及大致方向，但问题仍把“是否做、具体做什么、谁负责”挤在一起，不够聚焦。两者没有通过重采样隐藏。

### 原有难例的收益与负结果

六个原有难例及完整分工窗口冻结上游，只重新生成解释与核验。六例首次均完成；完整窗口首次出现 set 操作与时间字段不匹配，保留失败后用相同初版代码/提示恢复一次。审查修复后的最终程序又对这些输出做零模型 Service 重放，items/updates 完全一致。

| 同一冻结标签口径 | 上一版 | 当前版 |
| --- | ---: | ---: |
| 六难例内容命中 | 4/6 | 5/6 |
| 六难例内容F1 | 72.7% | 90.9% |
| 六难例完全正确召回 | 4/6（66.7%） | 3/6（50.0%） |
| 六难例完全正确F1 | 72.7% | 54.5% |
| 完整窗口内容命中 | 3/3 | 3/3 |
| 完整窗口完全正确 | 3/3 | 2/3 |

UI 和市场工作都留下了；“我们可以会后细化”恢复为建议，没有任务误报。但模型对承接更保守：C02 工业设计师的 Yep 被怀疑可能回应会议时间，已明确工作变成候选；市场工作也仍为候选，与冻结标签的创建主判定不同。市场标签本身注明短回应归属不确定，工业设计标签没有这一标记。不能只展示内容F1提高而隐去完全正确率下降。

C09 不再因日期缺口被阻断，但核验仍否认完整工作范围，只给笼统确认。它没有形成有用的隐式研究目的及具体范围问题，所以该内容仍漏。生产输出中不存在不合格自动创建提议，不代表正确承接已被可靠识别。

上述语义复核由本代理按原文与冻结标签完成，不是人工金标准。当前候选保留是执行层的保守处理，不能算模型已经正确理解了接受关系。默认策略不切换。

### 限定修正实验

隔离实验将原记录、原话和诊断反馈交给一次重新解释，只允许修改指定 record_id/thread_ids，再独立核验；不执行任务写入。这是有诊断提示的修正试验，不代表系统会自动发现并定位问题。

| 场景 | 一次修正结果 |
| --- | --- |
| 旧C03 UI漏项＋邮件通知反例 | 补回UI候选，邮件仍为纯上下文，没有变任务 |
| C26建议误判 | 恢复为建议，不输出任务，保留承接确认 |
| C09研究目的 | 仍没形成完整目的和针对性确认，失败 |

三次结构均成功，前两类行为符合目标，研究目的仍失败。自动修正流程未接入生产；研究目的、回应绑定和范围变更还需要新的正反例验证，不能用无限循环迫使核验通过。
