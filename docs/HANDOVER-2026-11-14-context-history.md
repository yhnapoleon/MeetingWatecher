## 用户目标与工作方式

产品目标为会议逐字稿 → 纪要和行动项 → 任务 → 下次会前回顾 → 跨会决策追踪。先保证用户得到完整、可信的工作内容。用原话、实际输出和失败位置解释问题；不要仅堆叠模型步骤或按案例 ID 修答案。用户已授权本轮调研、实施和检验，不需要重新申请同范围确认。

标注可以用代理初标与独立代理复核推进，但不得称为人工金标准。旧标签不因新结果变更；新增需求保留/确认准则另行冻结和评分。失败及恢复分别记录，不能对语义失败重采样挑好结果。

隐式/模糊需求不能自动写入；人工决定单独审计，不冒充会议承诺。加入任务需最终描述、明确账号映射与授权；旧任务关系未明不能回退新建。来源更新后不能确认旧记录，未发送旧意图也不能重发。写入成功但回执丢失时恢复只回读。

纯实体可保存而不转任务；实体相同、相关与任务相同分别判断。更新历史只能追加，证据不得来自未来段落。缺少可选截止时间不阻断工作，但已声明的时间若缺依据则不能直接执行。

## 验证结果

同样六个既有难例、各三轮，使用未改的 v2 标签：

| 版本 | 内容 F1 | 完全正确任务召回 | 每轮任务 token | 六例累计处理时间 |
| --- | ---: | ---: | ---: | ---: |
| evidence-v1 调整版，含一次恢复 | 75.2% | 55.6% | 62,206 | 224.1 秒 |
| context 初版 | 46.3% | 33.3% | 142,038 | 583.5 秒 |
| context 最终候选 | 71.1% | 50.0% | 100,884 | 361.8 秒 |

最终六例三轮均首次处理成功，行为准则分别为 12/17、11/17、13/17。新增流程、提示和推理配置同时变化，不能单独归因；处理耗时受服务负载影响。

连续 C02+C03 窗口首次有一轮引文结构失败，一次恢复后三轮内容 F1 都为 80%、完全正确召回都为 2/3，行为准则均为 2/4；UI 分工仍全部丢在核验后。

8 个中文合成样例首次 7/8 处理成功，任务命中 5/6、行为准则 17/21；同配置恢复 CP08 后为 8/8、6/6、19/21。6/8 例全部准则通过。它们是冻结的机制验证，不是新系列盲测。

最终 94 项程序测试通过。三轮双会议回放首次为 12/12、11/12、11/12；后两轮各恢复一次结构失败后均 12/12。旧证据实验汇总和规则重算通过，37 份成功任务阶段记录的提议不变。详见[测试日志](../runs/2026-11-14-context-implementation/final-tests.log)和[汇总](../runs/2026-11-14-context-implementation/comparison-summary.json)。

## 仍需解决的具体问题

- **C03 连续分工**：解释有时恢复了 UI 动作，但核验把未承接/省略视为工作内容无依据。短片段仅 1/3 合格，完整窗口 0/3；不能把“没答应”混成“没分过这项工作”。
- **C09 研究目的**：三轮都未形成保留用户看法/使用问题的合格具体确认。附上背景原话、泛泛问是否调查仍不够。
- **C20 混合工作**：第一轮把文稿动作不明与已承诺视频合并，连视频也被阻断。共享引文不代表同一任务。
- **C21 过度确认**：第二轮把“内容可能较长”当必须补范围，阻止已承诺的整理意见。
- **CP03/CP05**：撤回后仍残留问题；纯实体最终有记录，但实体账本为空。
- **确认噪声**：CP02 重问已完成对象核对，CP04 将保留不同结果的约束当独立工作。UI 可出现一张需求卡加三张原话卡；幂等只到同一记录 ID，手动确认多卡仍有重复任务风险。
- **结构失败**：跟踪/解释仍需生成精确引文，会把说话人元数据当正文；日期和证据结构也会失败。核验已改用证据编号，但不能据此声称整体稳定。

## 下一步建议

保留上下文记录与人工决定机制，先收窄到工作边界和字段判断：明确工作可以保留为待承接候选；模糊片段不能拖住旁边明确工作；目的、范围、承接和执行状态分别检查。针对 C03/C09 使用固定输入做小规模单变量对照，查看正确含义究竟在哪一步被删或压缩。

下一版先冻结“过度澄清、取消后问题残留、重复卡片”准则，再实验。实体/工作身份明确后再合并确认卡，不能只按引用重叠去重。现有难例稳定后再做完整开发集及新会议系列盲测。以上尚未实现或验证，当前不建议扩展所有检查点的模型职责。
