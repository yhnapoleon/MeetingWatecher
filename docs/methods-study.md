# 五个难点的架构取舍与对照实验

本月最有信息量的对照是让同一段讨论分别通过原始转写、人工校正转写和历史任务快照，观察错误最先出现在哪一步。本页按产品失败来选择技术。除[公开语料检索实验](corpus-study.md)外，表中的模型对照均为待运行方案。

## 1　多模态：从“这页第二项我来”恢复人和事

一句话里有三种指代：“这页”依赖画面，“第二项”依赖页面内容和顺序，“我”依赖发言人。把音频、逐字稿和幻灯片全部送给模型，即使最后猜对任务，也无法确认用了哪条依据。

| 比较条件 | 做法与可复用工具 | 观察什么 |
| --- | --- | --- |
| 妙记原始转写 / 人工修正说话人的同文 | 用同一文本、段边界和提取器，只切换说话人标签。标说话人归属、被指派者和最终账号三列。M3-SLU 提供按发言归属做问答、按原话匹配发言人的任务设计，可借其成对诊断方式。[M3-SLU](https://aclanthology.org/2026.lrec-1.451/) | 纠正标签后错人的任务是否恢复；仍错时检查“甲说由乙负责”及名册映射。标签缺失时统计正确留空率。 |
| 只有混合音轨 / 有分轨或视频 | 中文可试 FunASR 的 VAD、识别、标点与说话人模型，另用 WhisperX 的强制对齐作比较。用 pyannote.metrics 计算说话人分段错误率（DER），固定是否计入重叠以及边界宽容时长。MISP 的原论文在其条件下结合分离、微调和视听融合，使 CER 从 36.60% 降到 20.27%；该结果涉及多项改动。[FunASR](https://github.com/modelscope/FunASR) · [WhisperX](https://github.com/m-bain/whisperX) · [pyannote.metrics](https://github.com/pyannote/pyannote-metrics) · [MISP](https://aclanthology.org/2025.acl-long.753/) | 同时报 CER、发言时间归属和任务负责人准确数。有些单字错在人名、日期或否定词上，需单列对交付字段的影响。 |
| 原话 / 原话加当前共享页 / 原话加相邻错页 | 从自录的两张相似表格抽帧，记录显示开始和结束、页号、行列文字；按录制起点连接。先用切页关键帧与 OCR，遇到图示或布局指向再试视觉语言模型。演示文稿辅助识别的研究提示，页内专名是可测的一种增益。[论文](https://aclanthology.org/2025.emnlp-main.814/) · [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 评对象、证据页、时间窗；错页组用于识别模型是否盲从画面。页面未共享或时间窗跨越切页时，允许输出待确认。 |

预算优先给真实妙记导出与小段自录；如果正文、时间和承诺人都已足够，直接用文本抽取。只有需要从录音或共享画面恢复信息的样例承担多模态对照。

## 2　抽取：行动句、任务实例与可执行操作

多方对话里的任务可能跨越提议、讨论、承诺三个阶段。Purver 等研究先找形成任务的子对话，再抽取任务描述；AIMU 则把记笔记、查资料等助手可执行的意图连同参数一起标注。两者给出了不同的标注单位。项目可以保留“候选行动句”，在会后根据最终承诺生成“任务实例”，再根据账号、权限及原任务状态确定“操作”。这样“查一下刚发的邮件”就可以被识别为请求，同时保留应否创建会后任务的独立判断。[子对话抽取](https://aclanthology.org/2007.sigdial-1.4/) · [AIMU](https://aclanthology.org/L16-1117/) · [中文上下文识别](https://arxiv.org/abs/2303.16763)

| 基线 | 输入及输出 | 有价值的对照 |
| --- | --- | --- |
| 飞书原生待办 | 同场已有的妙记 todo，保存原文与可取得的字段 | 看原生功能已经做对哪些任务，以及缺在期限、指派还是持续追踪。生成条件和输入不可控，单列产品基线。 |
| 整场一次结构化抽取 | 原始转写、可见名册、会议时间 → 任务、决策、未决问题及引用 | 离线首选。用同模型、同输出格式比较“原始转写”和“只读自动纪要”；分开算压缩后漏掉的事实、模型凭空添加的事实。 |
| 候选窗口再抽取 | 句级分类或规则召回 → 扩展到承认、拒绝和改口 → 按交付物合并 | 记录候选召回率。用人工给定证据窗口再跑一次，是定位候选阶段损失的诊断。观察长会 token、跨窗口拆单与重复建单。 |

**标注一致性。** 两人先独立标同一小批，不给对方看正句列表。先比较事件数，再以交付动作、对象和证据做一对一匹配；在匹配任务上分别比较承诺人、被指派者、截止日期与证据范围。对“我周五整理，她周一确认”分两次交付；对“周五，不，改周一”保留原话和覆盖关系，最终期限只标周一。记录分歧是漏看、粒度不同、规则未定还是上游没有信息。规则修订后只重审受影响的类型。

**计分。** 任务重复抽两次，即使标题都正确也多一个 FP。与 gold 匹配后，分别检查字段和有无足够证据；同一条正确任务能否同时满足负责人、期限、写入目标，另报整条通过率。对纪要逐项核“已决、未决、依据、行动”，把缺失和无证据新增分开。已有会议摘要研究用人工错误分析检验自动指标，因此 ROUGE 等相似度只作为补充。若用 LLM 裁决同义改写，要对错人、错时态、否定、改口的人工裁决子集记录混淆矩阵，并保留裁决模型与提示版本。[会议摘要指标研究](https://aclanthology.org/2024.findings-emnlp.393/)

## 3　状态闭环：一条 GUID 如何跨两周保持正确

离线回放需要保存三样东西：会议中提出的变更、飞书实际任务状态、系统何时得知这个状态。“我昨晚发了”可在周二开会才录入；作周二会前回顾时，不能把会上的消息提前使用。任务表保留 GUID 与最新读回值，事件记录另存业务发生时间及系统观察时间。评分既比较最后的任务表，也检查会前快照和实际写操作。τ-bench 以最终数据库状态评工具代理，适合借鉴这种可检查结果；即使某次误发随后被撤回，本项目仍需从写操作日志发现它。[τ-bench](https://arxiv.org/abs/2406.12045)

| 注入条件 | 期望观测 |
| --- | --- |
| 创建已成功，响应超时，短时间重放 | 同一调用身份、同一持久化意图、同一 client_token；读回一个 GUID。 |
| 超时后隔天重放；或由用户身份切到应用身份 | 飞书幂等保证已不足以覆盖。先查本地 GUID 绑定及可访问清单中的唯一业务标识；不能确认时标“写入结果待核对”，不能按标题再造一条。[幂等约束](https://open.feishu.cn/document/task-v2/overview.md) |
| 人工完成 → 重新打开 → 会议前读取 | 会前清单出现原 GUID；模型的旧“已完成”记忆不能覆盖平台读回。 |
| 会签任务一人自报完成 | 标该人的进展；整体完成需要独立依据。飞书的完成 API 对会签与或签均为整体完成。[更新接口](https://open.feishu.cn/document/task-v2/task/patch.md) |
| 删除或无权读取 | 分别保存读回结果；无权读取不能推断任务完成。确认当前资源不可展示时不带旧缓存到回顾。 |

首版一个 SQLite 事务持久化待发操作和任务绑定，模拟器注入超时与重放即可。长时间跨进程执行、队列恢复成为实际需求时，再评估 Temporal。其活动重试仍需要外部操作自身具有幂等性；引入工作流引擎不会延长飞书的幂等窗口。[Temporal 活动](https://docs.temporal.io/activities) · [重试策略](https://docs.temporal.io/encyclopedia/retry-policies)

## 4　跨会关联：区分同一对象、相同话题、旧版和现行版

**与本题最接近的研究是 EvoWiki / CrossMeet（2026 年 8 月预印本）。** 作者按项目脚本生成中英文多次会议，将写入和查询拆开。写入时按“实体、属性”追加版本，旧值失效但保留会议出处；查询时按有效区间读取。例如，同一个人更改了交付日，只关闭截止日的旧版本，负责人和任务目标继续有效。CrossMeet 的会议是合成的，其证据链保留作追溯元数据，论文主评答案。这里值得借用的是按属性设计改期、撤回、替代的成对问题，另给证据段、被改的任务 GUID 和越权引用独立打分。论文读入整个 Wiki 的成本随体积增长，首版可以只取当前身份有权读的项目版本表。本次核查到论文和方法，尚未验证 CrossMeet 可下载的正式数据包。[论文及实验细节](https://arxiv.org/html/2608.23265v1)

设一个项目先定“首批只限员工”，下次扩到试点客户，另一项目也叫“首批灰度”。标注四类关系即可起步：同一任务的更新、替代旧决定、相关但独立、证据不足。候选选择必须在当时可知、当前可读的范围内，查询“当时决定什么”与“现在采用什么”分别标答案和来源。LongMemEval 把多会话、时间推理、知识更新与可否回答单独评，可直接借题型；其原始语料是助手对话。[LongMemEval](https://github.com/xiaowu0162/LongMemEval)

| 方法 | 具体比较 | 何时增加复杂度 |
| --- | --- | --- |
| GUID/显式来源 → 项目、对象、时间过滤 → SQL 版本表 | 保留两个相似项目各一个对象；检验明确链接、撤回和被替代关系。关系方向用三元组精确计分。 | 先交付，所有命中能解释到对象与版本。 |
| 词法候选 → 稠密召回或混合检索 → 重排 | SQLite FTS5 可做 BM25，本地中文先固定分词方案；短项目代号单测。BGE-M3 提供多语种稀疏、稠密等表示，可用同一授权候选池与 BM25 对照。记录 gold 是否进 top-k、重排后名次及错链率。[FTS5](https://sqlite.org/fts5.html) · [BGE-M3](https://arxiv.org/abs/2402.03216) · [FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding) | 显式链接缺失或同义改写使候选漏召回时。同一份会内、跨会以及不同对象的困难负例都要保留。 |
| 双时间版本表 → 时序图 | 以同一组已确认事实喂给两者，再单独比较自动抽边。测旧时点答案、现行答案、修订链完整率、无依据边数及成本。[Zep](https://arxiv.org/abs/2501.13956) · [Graphiti](https://github.com/getzep/graphiti) | 多次修订或跨对象依赖使版本查询难以表达时。必须区分检索收益与多做了一次 LLM 抽取的影响。 |

公开实验中，单场 top-1 窗口只覆盖了平均 20.22% 的人工证据。下一组有针对性的实验是“固定第一候选会议，合并最多三个不重叠窗口”，再与等 token 预算的连续窗口比较；增加输出长度本身就会提高覆盖率，因此同时报证据占比。[实验条件与错例](corpus-study.md)

## 5　权限：把同一个请求换个人再跑

授权测试的最小单位是“查看人、资源、关系、时间、动作”。同一人可能能看任务但看不到来源妙记，也可能曾经有权、现在已被移出。飞书的负责人和关注人具有不同的编辑能力，创建人、群分享、文档或清单协作也会改变有效权限。测试模型先用显式授权表表达平台已知结果；组织与清单的继承关系变复杂时，OpenFGA 的 Check 与 ListObjects 测试可以复用。授权模型必须通过真实测试身份与飞书结果对照。[飞书任务鉴权](https://open.feishu.cn/document/task-v2/task/overview.md) · [OpenFGA 模型测试](https://openfga.dev/docs/modeling/testing)

| 对照场景 | 正向检查 | 泄露或拒绝服务检查 |
| --- | --- | --- |
| 内部主持人 / 共享任务外协 | 外协能看到授权任务的交付与状态 | 内部妙记引文、会议名、候选数不出现在检索上下文和最终回顾。 |
| 相同显示名、不同租户 | 各自能查询本租户事项 | 用显示名关联或按查询文本共用缓存时，探针应检出串租户。 |
| 已有授权 / 会前撤权 | 撤权前能访问，撤权后读取权限重新生效判断 | 上次的摘要、向量候选、引用预览和缓存均不能继续泄露。 |
| 个人回顾 / 发到共享会议 | 个人可见事实完整；共享稿仅含收件人共同可见事实 | 切换输出对象时复制个人纪要会触发失败；测试只在模拟发送端记录接收者与内容。 |
| 只读关注人 / 可编辑负责人 | 两者均可读；只有具备编辑权的一方可更新 | 模型提议、写请求已发、平台写成功分开记录，检出越权尝试与真正副作用。 |

每对样例至少有一项合法内容。否则“全部不给看”的实现也能得零泄露。逐项报告合法任务召回、非法候选进入上下文、输出泄露、越权写请求和平台读回结果；现有清单脚本只覆盖最终返回的任务 ID。

## 本月实验顺序

1. **先完成成对标注。** 一条中文明确认领、一条会内安排、一个同名干扰、一组两人可见性差异。把输入和人工答案交给第二位标注者独立走读。此步即可发现哪些产品规则会让金标变动。
2. **同输入比较抽取。** 用当前可用的同一个模型固定提示、温度与字段，运行整场、候选窗口、人工证据窗口三种条件。记录每类错误数、每场成本、耗时及调用失败。多会议样本按会议系列做配对比较；样本少时直接报计数。
3. **回放会前与会后。** 固定抽取得到的操作，注入超时、手动完成、重新打开、撤权。用飞书测试空间核对一条真实创建及读回后，再决定是否扩展工作流系统。单独评模型重复运行时的整条链路成功率。
4. **按错例选择进阶技术。** 错在认人，比较分离和音频模型；错在画面指代，加入 OCR/视觉输入；错在候选缺失，做混合检索；错在选中旧版本，优先修复生效时间和关系标注。每个实验保留同批对照与引入成本，避免把多项变化归给一个组件。
