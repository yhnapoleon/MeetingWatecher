## 第一轮构建的实施顺序

### 1. 导入一场会，真实抽取并写入本地任务

统一接收两种已有输入。公开片段提供 segments 和可选 participants；模拟会议提供 started_at、timezone、speaker_map、roster、audience。导入时把这些信息映射为稳定的会议、发言、人员引用及访问范围，保留源字段供追溯。M2 的身份可从其 speaker_map 及已有会议名册解析。AMI 的原始日期是简写日期，缺失钟点和时区保持未知。

复用现有模型调用方式与证据校验，为完整会议输出增加关键事实、未决问题、任务、决策和更新建议。保留行动项输出到现有评分格式的转换。每项至少带原话引用，未知负责人、期限或历史目标可表达。

用 examples/m1.json 走正常入口，得到陈可承接的案例整理任务、11 月 13 日的交付日期、暂缓的监控面板提议及“首批只限员工”的决定。SQLite 保存会议、来源版本、抽取结果、任务候选、写入意图、GUID 绑定和回执。任务模拟器实际执行 create/get/update。

首次处理时持久化本地行动项 ID 和待发意图，重复导入相同来源版本时取回已有结果或绑定。一个发言段可能含多个交付，行动项去重要保留这一粒度。模拟器用于验证同一意图重放、创建成功后丢回执和进程恢复。

### 2. 接通会前回顾与第二场会后更新

在 M2 开始前读取任务状态，以 host 与 guest 分别生成回顾。样例的 T18、T19 可作为模拟平台中已有的外部任务预置；T17 应由 M1 的真实处理结果建立。若模拟器分配其他 GUID，评分端通过绑定映射到样例中的 T17，并验证后续沿用同一 GUID。

截至 2026-11-16 09:59:59，host 应见 T17、T18，guest 应见 T18。会后处理 M2，按试行规则将负责人自报交付关联到原任务，模拟器确认完成后更新读回状态；将灰度范围保存为 D2，记录 D2 替代 D1，并保留两版证据。

业务发生时间和系统获知时间分别保存。会前查询只使用截至当时已获知的信息。后续历史查询仍按查询者当前权限过滤。回放测试中，每个查询事件同时给出历史截止时点和当次授权环境。

### 3. 输出可用的纪要与决策查询

每场会输出一份可读纪要，包含关键事实、行动项、已决事项、未决问题及发言引用。提供查询同一项目某属性当前决定、历史决定及来源的入口。对任务更新优先用显式 GUID 或绑定，再用项目、交付物、负责人及证据定位；无法唯一定位时保存待关联结果。

SQLite 版本表足以承担首轮决策查询。检索扩展可在实际出现候选漏召回后使用项目已有词法检索经验。同名项目、相关但独立事项和明确替代关系分别验证。

### 4. 用现有评分器跑通验收并留比较结果

先验证完整 M1 → 会前回顾 → M2 更新，再跑六个状态与权限样例。接着让新程序从正常导入和抽取入口处理开发集，导出兼容预测文件，与首轮基线比较。结构正确、业务结果、模型错例、耗时和用量分别记录。

首轮交付应包含一个有运行说明的回放入口、持久化 SQLite 数据库、可读纪要与查询结果、模型输入输出、操作日志及评分报告。每个模块接上上述链路后再按实际错误补充实现。

## 开发沿用的试行规则

| 情形 | 当前规则 |
| --- | --- |
| 自我承诺或被指派后明确承接 | 身份可解析时进入可新建操作；原话和承接证据一起保存。 |
| 明确指派未承接、条件性承诺、团队承诺、只有会内编号 | 保留候选及原因。候选同样参与行动项检出评测。 |
| 负责人自报完成 | 在单负责人、目标唯一的情况下提议完成，适配器回执与读回确认后记录任务已完成；会签只汇报个人进展。 |
| 模糊日期、工作时段 | 保留原文和精度；仅在有足够参照信息时归一化截止日期。 |
| 读取与写入权限 | 在给模型供数前按租户、项目、查看人和时点限制候选，写入时另核执行权及目标受众。任务与来源妙记分别判权。 |
| 状态读取失败或回执未知 | 显式记录未知状态或待核对意图，后续恢复沿已有绑定查询。 |

这些规则是当前离线实现依据，业务方后续确认线上策略时更新规则版本和受影响样例。AMI 人员代号、host/chen 等测试别名通过模拟映射工作；实际飞书适配器需要可核实的平台账号映射。
