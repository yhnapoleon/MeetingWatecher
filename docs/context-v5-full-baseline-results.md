# context-v5 全输出专项回归：98/115通过

> 指标定位已按用户反馈修正：本文件统计整例全部输出，不是任务准确率。当前主报告为[任务精确率与召回率](context-v5-task-metrics.md)；两例纪要partial不作为任务扩集前置门槛。原分数与诊断保留。

2026-11-17。当前方案在一次完整执行中，115个场景有113个完成交付，其中98个通过逐例原文复核。**端到端通过率85.2%，完成样例中的语义正确率86.7%，技术交付完成率98.3%。** 本轮支持继续建设独立新数据集，但还不能据此宣称方案已具备广泛普适性。任务侧新集评测的优先级以任务主报告为准；此处事实、纪要及未决错误作为分项诊断保留。

## 本轮怎样执行与计分

旧全量入口有95个场景，未包含后来新增的20个semantic-v1场景。因此本轮一次性运行95+20=115个场景，分层报告。113个是单会议场景，另2个是M1→M2跨会议链路；每条链路同时要求两次处理及实际状态更新正确。已有样例均参与过研发，属于回归材料。

运行前冻结输入、标签、评分规则、代码、提示词与推理配置。模型返回标识均为deepseek-flash，4个worker并发，每例只执行一轮。上下文跟踪和工作解释采用high思考、16,384输出预算；预算耗尽时按既有机制扩至32,768，工作核验关闭思考。完整配置与每次请求见运行目录。没有人工追加恢复额度，也没有整例重跑选最好结果。

评分规则在生成前写入[冻结清单](../runs/2026-11-17-full-baseline/manifest.json)。技术完成要求processed且无提取错误；语义复核覆盖事实、决定、未决、工作主体/范围/条件/时间、确认问题及实际写入。任一必需内容遗漏或实质含义错误，整例不通过。semantic-v1明确要求进入unresolved的命题，不能用facts或任务描述代替。原文没有真实工作时，单纯系统分类诊断不等于新增业务义务；但应做的工作缺失仍计失败。

115例均由助手对照原文逐例审计，判定与输入、结果文件哈希绑定；这不是独立人工盲评。未知信息、等价表述和可选省略按冻结规则处理，不采用关键词命中作为语义分数。

## 两例未完整交付：协议恢复成功后，语义核验仍阻塞

**角色上下文CTX_ES2002a_roles。** 三项角色工作正确提取。初稿将“所有人收到指示邮件”误写为PM发送；修正稿已改成“PM表示所有人都会收到通过电子邮件发送的指示”，复核模型仍沿用“把PM当发送者”的旧异议。复核输出的内容判定与异议处置还不一致，最终F5未通过。所有模型节点都已被协议层接受，系统却将整组facts/unresolved清空，返回partial。

**CP01。** 小林最终承接移动端设置页功能清单，范围和承接均正确；背景句“开关名称还没统一”却被扩展为“具体如何统一尚未确定”的未决问题。修正没有消除扩展，复核仍判content=insufficient，同时又将issue_checks标为resolved。系统按较严格的内容判定阻止整组纪要交付。工作分支还多问了是否安排统一命名。该例此前发生的length耗尽已通过扩大预算恢复，缺闭合符也已本地恢复，最终阻塞不是HTTP、JSON或重试次数问题。

两例的共同放大机制位于[minutes_review.py](../meeting_eval/minutes_review.py)：修正后任一命题仍未核验，就抛异常并清空整个facts/unresolved结果，包括此前已通过的命题。后续应设计命题级隔离，保留可靠内容和显式未完成标记；对修正前异议与修正后文本不一致的情况做有限复核。不能直接把未通过的句子视为正确，也不能把缺少必需纪要的partial改名为成功。具体日志见[未完成诊断](../runs/2026-11-17-full-baseline/incomplete-diagnoses.json)。本轮没有修改生产实现。

## 15例语义错误的分布

| 类别 | 场景 | 具体错误 |
|---|---|---|
| 事实的时间、条件或否定 | C02、C14、C16、C18、HT06 | ten to twelve译错；条件调查或probably被概括为确定承诺；电视被误放入排除范围；案例时间被确定为发送时间 |
| 工作、指代与引用边界 | C03、C09、C20、C24 | 已有UI角色仍被问负责人；已答且承接的说明书调查漏掉；文稿提及被补成动作；历史教师举例被当成本场工作 |
| 承接判断及确认问题 | TU10、P06b | 本人明确取消期限仍被当成未确认，旧日期未清；尚未决定做什么，却询问既有工作是否由负责人承接 |
| 未决事项遗漏或误暂缓 | SV03、SV08、SV12、SV15 | 准点率、成本差、离线检索能力未知未进unresolved；“尚无结论”被改为暂缓。SV15另漏“现在就开始”的要求 |

TU10沿数据流可定位到工作解释把commitment写为unknown，虽然time.change已经正确为clear，后续执行门槛因此拒绝清除日期；这不是数据库写入失败。它影响实际任务状态，应保留定向验证。其余错误不在本轮追加模型请求修复。

semantic-v1共10个必需未决命题，本轮在指定栏目正确保留6个，遗漏4个，召回率60%；未发现不受原文支持的新增未决命题。这个分项仅指20例专项，不能扩写成全115例都没有误增。SV19额外收录“具体工作由谁承接未定”，有原文“没有人承接具体工作”支持，未作为无依据新增。

## 恢复、用量与可复核性

750个真实请求，已知总用量3,928,459 token，未知用量请求0。9个节点首轮失败后追加一次请求并成功：2个预算耗尽、3个语法错误、4个协议/引用校验错误。另39个节点通过本地无损结构规范化恢复，没有为这些本地修复增加请求。没有最终exhausted/recovery_required、waiting_retry或terminal_error节点。节点协议通过不等于语义正确，也不意味着整个场景完整交付。

## 能否扩大数据集

可以开始独立采样与标注，但当前结果只说明已知回归集上的表现。30个自然核心片段来自20场原始会议、15个系列；18个英文AMI片段集中在3个遥控器设计系列。加上一个扩展上下文，自然片段仅31/115，其余84例是构造或改写场景。当前分布不足以支撑跨领域、长会议或真实生产准确率结论。[来源索引](../runs/2026-11-17-full-baseline/source-groups.json)

下一批协议已形成：先用12例试验标注流程，再冻结60例，其中40例自然会议至少覆盖30场原会议，20例为10对机制对照；按原会议/系列隔离开发与测试，补充不同领域和长上下文。先标注、后预测，自然会议与控制对照分别报告。若只有助手审计，明确披露，不能称为双人独立盲评。[独立泛化数据协议](generalization-dataset-protocol.md)

按用户对主指标的纠正，保持本次基线不变，继续推进任务级新数据标注；TU10保留为真实更新缺口的定向用例，纪要阻塞不作为任务扩集门槛。正式60例只在代码与任务标签冻结后执行一次。扩集不必等待所有语义错误消失，也不应使用新集预测结果倒推选样。本文完成的是基线执行、全量复核和扩集协议，尚未采集或运行新增60例。
