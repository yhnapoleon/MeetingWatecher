# semantic-v1：模型输出前冻结的命题验收数据

2026-11-16。数据版本为 `semantic-v1`，见 [semantic-v1.json](../../experiments/task-boundary/semantic-v1.json)。

本版本用于判断纪要是否保留真实未知、删除已关闭或没有本场资格的问题，以及工作系统是否创建了无依据的任务或追问。包含 **6 个旧场景的回归命题标签和 20 个新输入**。每个新输入有 2–3 段发言，沿用原 fixtures 的人员、权限和 meeting 结构，并显式指定 `actor=host`。正规入口归一化后，人员引用和 account_map 与原 fixtures 一致。

数据由本次研究任务中的助手依据源文本及已批准设计编写，没有调用评测模型，也没有取得这 20 个新输入的预测。“冻结”表示在新预测前固定输入和判断规则；**本版本不是独立人工金标，也不是模型效果验证结果**。六个旧场景是在阅读历史审计后建立的回归标签，不得报告为未见测试。新输入虽然没有预测可供观察，但与旧问题共享设计机制，不能据此声称代表全部分布外场景。

## 标注的使用口径

- **required**：必须保留的命题或工作行为。`required_facts`、`required_unresolved` 分别指定纪要栏目，工作要求在 `work_expectation.required` 中单列。允许同义改写、合并和拆分，仍须保留角色、对象、条件和最终状态。
- **optional**：允许记录，也允许省略。可选项不计入召回分母，缺省不判失败；若输出，仍需由原文支持。
- **forbidden**：不得出现的误读或行为。这些约束不是让模型在纪要中逐条输出否定句。
- `required_unresolved` 为空，仅表示没有强制保留的未知；其他输出仍按原文与 forbidden 核验。不得因某个工作分类就推断纪要必须或不得存在未决。
- 证据 ID 对应冻结输入段落。正规入口转换成 Q 编号后，评阅需保留回溯关系；不得把评测标签传入生成上下文。
- 本数据不附关键词打分器。后续应对固定预测逐项核验命题，分别记录 required 遗漏、forbidden 误读、真实未知保留和无依据追问，并披露评阅身份及是否盲评。

## 六个旧场景的边界

| 场景 | required | optional | forbidden 的关键边界 |
|---|---|---|---|
| C09 | 说明书是已确定研究对象；营销研究工作保留 | 说明书使用背景；研究细节未穷尽的审慎说明 | 重开对象选择；宣称研究结果和所有维度已确定 |
| C13 | 产品未纳入语音识别，发言者接受结果 | 带保留回顾、反事实评价、按旧标签记决策 | 将未实现当成未决；从完整会议补入管理层建议 |
| P05a | 无强制纪要命题 | 培训引用事实 | 材料未展示答案被改成本场未决；创建核对或发群工作 |
| P05b | 小林已承接本园名单核对 | 培训背景及本次安排 | 用本次核对任务替发群许可问题补上本场采用依据 |
| P06a | 无强制纪要命题 | 过去问句的举例事实 | 将恢复设置问题列成本场待答或建立工作 |
| P08b | 支持能力仍未知；小林是查询者；沿用旧 conditional 契约 | 支持对象未指明的明确说明 | 调查者变支持者、查询信息变录像文件、补入设备或会议对象 |

C09 只裁定冻结的 12 段输入，不要求虚构研究结果未知；C13 只裁定冻结的 6 段输入，不将整场会议中未提供给模型的内容拿来补证。旧例的命题标签依据原输入和审计理由编写，不把历史模型输出复制成标准答案。

P08b 原 `conditional=true` 和完整 expectation 保存在 policy 中。没有修改 expectations、manifest 或历史分数；结果不保证与启动条件的差异只在新例 SV15/SV16 中评价。C11 的产品备选可以记录；没有本场待选要求时，不强制新增当前未决，也不因 `context_only` 自动删除合法未知。

## 新输入的对照关系

| 输入 | 语义变化 | 必需结果与禁止误读 |
|---|---|---|
| SV01 / SV02 | 培训问句未采用 / 明确纳入本场 | SV01 无当前许可未决；SV02 必须保留许可未知；不得自动创建已承接工作 |
| SV03 / SV04 | 研究对象已答 / 对象仍未选 | SV03 保留准点率未知并关闭对象选择；SV04 保留范围选择，不能重复追问承接 |
| SV05 / SV06 | 两个问题只答一个 / 全部回答 | SV05 只保留讲义版本未决；SV06 不重开已答的地点和版本 |
| SV07 / SV08 | 接受产品结果 / 重新开放选择 | 未实现不自动构成未决；明确重新开放时必须保留选择 |
| SV09 / SV10 | 文稿仅列名称 / 文稿也须编辑并发送 | SV09 只保留海报工作；SV10 必须保留两项动作及各自对象 |
| SV11 / SV12 | 产品备选 / 明确安排成本评估 | SV11 可选记录备选，不强制待决；SV12 必须保留评估工作及未知成本差额 |
| SV13 / SV14 | 过去工作完成汇报 / 过去培训引用 | SV13 保留 completed 汇报；SV14 不变成本次工作或事实 |
| SV15 / SV16 | 即刻查询但结果不保证 / 权限开通后才查询 | SV15 不生成启动条件追问；SV16 必须保留真实前提，两个例子均保留能力未知 |
| SV17 / SV18 | 按日期暂缓 / 按信息到齐暂缓 | 两例均必须在纪要保留议题和再议安排，不列立即未决，也不启动工作 |
| SV19 / SV20 | 当前目标需求 / 其他园所目标的引用 | SV19 必须保留真实 implicit_need 和未定方式；SV20 不产生本园需求 |

20 个新输入共有 16 项 required 事实命题、10 项 required 未决命题。部分复合事实允许拆分为多句，计数只是标签单元数量，不是要求模型输出固定条数。SV10 允许两个任务或保留两项动作及各自对象的复合任务，不以任务拆分方式替代语义判断。

这组输入覆盖设计第 1–8 类语义变化、第 11 类暂缓的恒定输出要求，以及当前目标需求的正反对照。第 9 类“首检正确但原样修正／首检误判但可推翻”需要原候选、异议和修正状态；第 10 类“同名旧任务／唯一旧任务”需要历史任务库。本文件不提供这两类状态夹具，不能据这些短输入宣称已覆盖它们。

SV17/SV18 还须分别组合工作分支成功、失败、漏提，以及展示关联过期进行机制验收。标签规定各状态下纪要暂缓事实均须可见；已核验关联可合并重复展示，关联过期不能隐藏事实。当前文件只固定这一语义要求，没有执行上述故障注入。再议条件也不自动建立收集数据的工作。
